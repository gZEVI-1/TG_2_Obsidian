# Этап 14: автоматические резервные копии

## Этап

Этап 14 — копии по расписанию, пока бот запущен: `BACKUP_EVERY_HOURS`,
копия при старте, если предыдущая просрочена, и проверка раз в час.
Дополняет ручной `--backup` из [13_health_backup.md](13_health_backup.md).

## Цель

Сделать так, чтобы:

- копии не зависели от того, вспомнит ли владелец про `--backup`;
- после долгого перерыва копия появлялась сама при первом запуске бота;
- `--health` показывал возраст последней копии и честно предупреждал, если
  она просрочена;
- при выключенном расписании (`BACKUP_EVERY_HOURS=0`) всё работало по-старому,
  только вручную.

## Что сделано

- `app/config.py` — `BACKUP_EVERY_HOURS` (0–720, по умолчанию 24; 0 — только
  вручную), значение видно в `--check-config`.
- `app/backup.py` — три функции поверх `create_backup()`:
  - `last_backup()` — время самой свежей копии (по `mtime` файлов
    `tg-obs-backup-*.zip`), `None` — копий нет;
  - `backup_due()` — пора ли делать копию: нет копий, интервал истёк или
    расписание выключено/каталог не задан (тогда `False`);
  - `backup_if_due()` — делает копию, только если она просрочена, иначе
    возвращает `None`. Отдельного файла состояния нет: источник правды —
    сами архивы, поэтому копия, сделанная вручную, тоже считается.
- `app/bot.py` — фоновая задача `_auto_backup()`: при старте сразу проверяет
  `backup_if_due()` (догоняет пропущенное), дальше спит по часу и проверяет
  снова; копирование идёт в `asyncio.to_thread`, чтобы не блокировать
  обработку сообщений; ошибки (`ValueError`, `OSError`) только пишутся
  в лог, бот продолжает работу; задача отменяется при остановке.
- `app/health.py` — строка `копии` теперь показывает возраст последней копии
  и интервал, а при просроченной копии меняет `ok` на `warn`:
  `последняя 30.10 02:47 (каждые 24 ч)` или `просрочена (каждые 24 ч)`.
- `tests/test_backup.py` — 6 тестов расписания: копий нет, свежая копия,
  истёкший интервал, `0`, пустой `BACKUP_DIR`, `backup_if_due` создаёт ровно
  одну копию.
- `tests/test_health.py` — 3 теста строки `копии`: свежая (`ok`), просроченная
  (`warn`), ручной режим.

## Внешние действия

Не требуются: расписание включено по умолчанию (24 часа) и работает, пока
запущен бот. Если копии нужны реже или чаще — одна строка в `.env`:

```dotenv
BACKUP_EVERY_HOURS=24
```

`0` выключает автоматические копии — остаётся `python -m app --backup`.
Каталог `BACKUP_DIR` по-прежнему обязателен и не должен лежать внутри
хранилища.

## Принятые решения

- **Таймер внутри бота, а не служба/Планировщик.** Автозапуск отложен до NAS
  (ADR-44), а ставить отдельную задачу Windows ради копий — это второй
  механизм запуска. Бот и так работает, пока владелец им пользуется.
- **Копия при старте, а не только по таймеру.** Бот запускают вручную и
  ненадолго; если ждать 24 часа от запуска, копий не будет никогда. Проверка
  «просрочена ли последняя» при старте закрывает это.
- **Источник правды — файлы копий, а не запись в `state/`.** Нет отдельного
  состояния, которое может разойтись с реальностью; копия, сделанная
  вручную, сбрасывает таймер автоматически.
- **Копия не блокирует чат.** `asyncio.to_thread` — чтение сотен файлов
  и сжатие не должны задерживать ответы.
- **Ошибка копии не роняет бота.** Нет доступа к диску — предупреждение
  в лог и `warn` в `--health`, остальное работает.
- Отклонено: копия при каждом запуске бота (лишние архивы и нагрузка),
  удаление старых копий по дате (уже есть ротация по числу).

## Как проверить

```powershell
cd E:\FOLDER\TG-OBS\TG_2_Obsidian
.\.venv\Scripts\python.exe -m unittest discover -s tests    # 246 тестов, OK
.\.venv\Scripts\python.exe -m app --health
```

Ожидаемая строка (проверено 30.10.2026):

```
app.health: копии            ok    E:\FOLDER\TG-OBS\backup: последняя 30.10 02:47 (каждые 24 ч)
```

Проверка «догоняющей» копии без ожидания суток:

```powershell
# пустой каталог и интервал 1 час: копия появится при старте
$env:BACKUP_DIR="$env:TEMP\tgobs-auto"; $env:BACKUP_EVERY_HOURS='1'
# запустить бота и через несколько секунд посмотреть каталог:
Get-ChildItem $env:TEMP\tgobs-auto
```

Второй запуск в тот же час новой копии не делает — интервал не истёк.
Просроченную копию видно в `--health` как `warn … просрочена`.

## Риски и откат

- **Копии только пока бот запущен.** Месяц без запуска — месяц без копий;
  это цена отказа от службы. `--health` покажет возраст и предупредит.
- **Спящий/выключенный ПК.** Пока компьютер спит, таймер не идёт; после
  пробуждения проверка произойдёт при следующем часе или следующем старте.
- **Большое хранилище.** Копия читает все `.md` и сжимает их: на сотнях
  мегабайт это заметная нагрузка на диск. Интервал можно увеличить.
- **Копия на том же диске не спасает от отказа диска.** `BACKUP_DIR` лучше
  держать на другом носителе или в синхронизируемой папке (но не внутри
  хранилища).
- **Часы.** При переводе времени назад копия может считаться свежей дольше
  обычного; на интервале в сутки это несущественно.
- **Откат.** `BACKUP_EVERY_HOURS=0` — остаётся только ручной `--backup`;
  код — убрать `_auto_backup` из `run_bot`, функции расписания из
  `app/backup.py`, строку из `app/health.py`.
