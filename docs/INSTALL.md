# Установка и запуск: инструкция для самых маленьких

> Эта инструкция рассчитана на человека, который **никогда не запускал
> Python-ботов** и не хочет разбираться в терминах. Делайте шаги по порядку,
> копируйте команды целиком. Если что-то не получилось — в конце есть раздел
> «Если что-то пошло не так» почти на каждый случай.

**Что мы сделаем:** подключим ваш Telegram к вашему хранилищу Obsidian через
бота, который умеет создавать, дополнять и искать заметки с помощью AI.

**Сколько времени:** 30–60 минут, из них большая часть — установка и получение
ключей.

**Что нужно уметь:** открывать сайты, скачивать файлы, запускать программу и
вставлять команды в окно терминала. Всё остальное объясним.

## Что получится в итоге

Вы открываете Telegram, находите своего бота и пишете:

> «Запиши: завтра в 10:00 созвон с Иваном, обсудить сроки релиза»

Бот предлагает заметку, показывает текст, спрашивает папку и после вашего
«да» создаёт в вашем хранилище Obsidian файл `Inbox/Созвон с Иваном.md` с
заголовком, датой и разделом для задач.

Вы можете закрыть Obsidian — бот продолжит работать, потому что в файловом
режиме он пишет `.md`-файлы напрямую.

## Что понадобится

| Что | Зачем | Сколько стоит |
|---|---|---|
| Компьютер (Windows, macOS или Linux) | на нём будет работать бот | — |
| Интернет | Telegram, модель, первая загрузка | — |
| [Obsidian](https://obsidian.md/) | ваше хранилище заметок | бесплатно |
| Аккаунт Telegram | интерфейс бота | бесплатно |
| Ключ LLM (например, OpenRouter) | «мозг» бота | есть бесплатные модели |
| 30–60 минут | установка | — |

Компьютер должен быть **включён и подключён к интернету**, пока вы пользуетесь
ботом. Telegram — это только пульт; сам бот живёт на вашей машине.

## Три вещи, которые стоит понять сразу

1. **Бот — это программа на вашем компьютере.** Она запускается командой в
   терминале и общается с Telegram через интернет. Закрыли терминал — бот
   перестал отвечать.

2. **Хранилище Obsidian — это обычная папка с файлами `.md`.** Внутри неё есть
   скрытая папка `.obsidian` — по ней легко узнать, что вы выбрали правильную
   папку. Бот читает и пишет эти файлы.

3. **LLM — это внешний сервис, которому бот отправляет текст запроса и заметок,
   чтобы понять смысл.** Без ключа LLM бот не сможет принимать решения. Ключ —
   как пароль: никому его не показывайте.

## Шаг 1. Установите Python

Боту нужен **Python 3.11 или новее**. Если вы не знаете, что это, — просто
установите по инструкции ниже.

### Windows

1. Откройте <https://www.python.org/downloads/>.
2. Нажмите большую жёлтую кнопку **Download Python 3.x.x**.
3. Запустите скачанный файл.
4. **Самое важное:** на первом экране поставьте галочку
   **«Add python.exe to PATH»** (внизу окна). Без неё команда `python` не будет
   работать.
5. Нажмите **Install Now** и дождитесь окончания.
6. Закройте установщик.

Проверка. Откройте меню «Пуск», напишите `PowerShell`, запустите
**Windows PowerShell** и введите:

```powershell
python --version
```

Ожидается что-то вроде `Python 3.13.2`. Если вместо этого открылся Microsoft
Store или написано, что `python` не найден:

- попробуйте `py --version`;
- если и это не работает — переустановите Python и **обязательно** поставьте
  галочку «Add python.exe to PATH».

> 💡 Если вы уже ставили Python и не уверены, какая версия используется, команда
> `py --version` покажет версию, которую запустит установщик Windows. В
> дальнейшем вместо `python` можно везде писать `py` — разницы для нас нет.

### macOS

1. Скачайте установщик с <https://www.python.org/downloads/> и установите.
   Либо, если у вас есть Homebrew:

   ```bash
   brew install python@3.12
   ```

2. Проверьте:

   ```bash
   python3 --version
   ```

   В командах создания окружения ниже используйте `python3`. После активации
   `.venv` команда `python` тоже работает — внутри окружения она указывает на
   нужную версию.

### Linux

В Ubuntu/Debian:

```bash
sudo apt update
sudo apt install python3 python3-venv python3-pip
python3 --version
```

В Fedora:

```bash
sudo dnf install python3 python3-pip
```

## Шаг 2. Установите Obsidian и создайте хранилище

Если Obsidian у вас уже есть и вы знаете, где лежит папка хранилища, этот шаг
можно пропустить.

1. Скачайте Obsidian с <https://obsidian.md/> и установите.
2. При первом запуске выберите **Create new vault** (Создать новое хранилище).
3. Назовите его, например, `TG-OBS-Test`, и выберите папку, например
   `Документы`.
4. Нажмите **Create**.

> ⚠️ Для первых экспериментов лучше сделать **отдельное тестовое хранилище**.
> Когда убедитесь, что всё работает, подключите основное.

**Где находится папка хранилища?** Это папка, которую вы выбрали при создании.
Внутри неё лежит скрытая папка `.obsidian` и ваши заметки. Если сомневаетесь:

- **Windows:** откройте проводник, зайдите в папку и щёлкните по адресной
  строке сверху — путь подсветится, его можно скопировать.
- **macOS:** щёлкните по папке правой кнопкой → `Copy` → `Copy as Pathname`
  (в Finder: правый клик с зажатым `Option`).

Пример пути: `C:\Users\Анна\Documents\TG-OBS-Test`.

> 💡 Не указывайте в качестве пути саму папку `.obsidian` или отдельный файл
> заметки. Нужен именно корень хранилища — папка, в которой лежат `.obsidian` и
> заметки.

## Шаг 3. Подключите хранилище Obsidian

Есть два способа. Выберите **один**.

| | Файловый режим (`vault`) | Local REST API (`rest`) |
|---|---|---|
| Obsidian должен быть запущен | **нет** | да |
| Нужен плагин и ключ | нет | да |
| Что использует бот | файлы `.md` напрямую | HTTP-сервер внутри Obsidian |
| Поиск Obsidian (алиасы, теги) | частично | полный |
| Сложность настройки | низкая | средняя |
| Кому подойдёт | почти всем, особенно новичкам | если нужен полноценный поиск Obsidian |

### Вариант A. Файловый режим (рекомендуется)

Ничего дополнительно устанавливать не нужно. Достаточно пути к хранилищу,
который вы получили на предыдущем шаге. В `.env` позже будет:

```ini
OBSIDIAN_MODE=vault
OBSIDIAN_VAULT_PATH=C:/Users/Анна/Documents/TG-OBS-Test
```

Всё. Obsidian можно даже закрыть.

### Вариант B. Local REST API

Понадобится, если хочется, чтобы бот пользовался поиском Obsidian по алиасам и
тегам, или если вы уже работаете через этот плагин.

1. Откройте Obsidian.
2. Нажмите **Настройки** (шестерёнка слева внизу).
3. Выберите **Сторонние плагины** (Community plugins).
4. Нажмите **Включить сторонние плагины** (Turn on community plugins) и
   подтвердите.
5. Нажмите **Обзор** (Browse), найдите в поиске **Local REST API**.
   Автор — `coddingtonbear`. Не путайте с похожими плагинами.
6. Нажмите **Установить** (Install), затем **Включить** (Enable).
7. В списке плагинов найдите **Local REST API** → **Параметры** (Options).
8. Скопируйте **API Key** — длинную строку из букв и цифр. Это ключ доступа к
   вашему хранилищу, никому его не передавайте.
9. Убедитесь, что включён **HTTP Server** и порт **27123** (по умолчанию).
   HTTPS-порт `27124` можно не трогать.
10. Оставьте Obsidian запущенным. Если закрыть приложение — сервер перестанет
    отвечать, и бот не сможет работать в этом режиме.

В `.env` позже будет:

```ini
OBSIDIAN_MODE=rest
OBSIDIAN_BASE_URL=http://127.0.0.1:27123
OBSIDIAN_API_KEY=вставьте-ключ-из-плагина
```

> 🔒 Ключ и порт работают только на вашем компьютере (`127.0.0.1`). Если
> Windows спросит про доступ к сети для Obsidian, локального доступа достаточно;
> открывать порт в интернет не нужно и опасно.

## Шаг 4. Создайте Telegram-бота и получите токен

1. Откройте Telegram и найдите **@BotFather** (у него синяя галочка).
2. Нажмите **Start**.
3. Отправьте команду:

   ```text
   /newbot
   ```

4. BotFather спросит **имя бота** — то, что увидят пользователи. Например:
   `Мои заметки`.
5. Затем спросит **username** — он должен заканчиваться на `bot`, например:
   `my_obsidian_notes_bot`. Если имя занято, попробуйте другое.
6. В ответ BotFather пришлёт примерно такое:

   ```text
   Use this token to access the HTTP API:
   7123456789:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```

   Это и есть **токен**. Скопируйте его целиком.

> 🔒 Токен — это полный доступ к боту. Не публикуйте его, не отправляйте
> друзьям и не вставляйте в скриншоты. Если токен утёк — в BotFather выполните
> `/revoke` и получите новый.
>
> Имя бота тоже лучше не афишировать. Список разрешённых пользователей есть —
> `TELEGRAM_ALLOWED_USERS` (см. «Безопасность»), но пока он пуст, бот отвечает
> любому чату.

Меню команд бот настроит сам при первом запуске — вручную через BotFather
ничего настраивать не нужно.

## Шаг 5. Получите ключ LLM

LLM — это модель, которая понимает ваши фразы и решает, какой инструмент
вызвать. Бот работает с любым **OpenAI-совместимым** API.

### OpenRouter: бесплатный вариант

1. Откройте <https://openrouter.ai/> и зарегистрируйтесь (можно через Google
   или GitHub).
2. Перейдите в раздел **Keys** (в профиле справа).
3. Нажмите **Create Key**, дайте название, например `tg-obs`.
4. Скопируйте ключ вида `sk-or-v1-...`. Он показывается **один раз** — сохраните
   его в надёжном месте.
5. Откройте <https://openrouter.ai/models> и выберите модель. Вам нужна модель:
   - с пометкой **free** (если хотите без оплаты);
   - с поддержкой **tools / function calling** — иначе бот сможет болтать, но
     не сможет создавать заметки.

   На странице модели поддержка инструментов обычно указана в списке
   параметров или возможностей. Скопируйте **точный ID** модели, например
   `vendor/model-name:free`.

> ⚠️ Бесплатные модели и их доступность меняются. Если указанная в примере
> модель перестала работать, выберите актуальную на сайте OpenRouter и
> подставьте её ID в `LLM_MODELS`.
>
> ⚠️ Если модель не поддерживает tool-calls, бот будет отвечать текстом, но
> ничего не создаст. Проверка `--check-llm` покажет это предупреждением.

### Другие провайдеры

Подойдёт любой сервис с OpenAI-совместимым API и поддержкой инструментов.
Примеры адресов (проверяйте актуальность в документации провайдера):

| Провайдер | `LLM_API_1_BASE_URL` | Комментарий |
|---|---|---|
| OpenRouter | `https://openrouter.ai/api/v1` | много моделей, есть бесплатные |
| OpenAI | `https://api.openai.com/v1` | платно, стабильные tool-calls |
| DeepSeek | `https://api.deepseek.com/v1` | дешевле, проверьте tools |
| Groq | `https://api.groq.com/openai/v1` | быстрый, модели с tools |
| Ollama (локально) | `http://127.0.0.1:11434/v1` | бесплатно, ключ — любая строка, например `ollama` |

Для локальной Ollama модель тоже должна уметь вызывать инструменты. Проверьте
это в её описании; слабые модели часто игнорируют tools.

### Несколько аккаунтов

Можно указать несколько ключей — бот будет переключаться между ними при
лимитах:

```ini
LLM_API_1_NAME=main
LLM_API_1_BASE_URL=https://openrouter.ai/api/v1
LLM_API_1_KEY=sk-or-v1-ключ-первого-аккаунта

LLM_API_2_NAME=second
LLM_API_2_BASE_URL=https://openrouter.ai/api/v1
LLM_API_2_KEY=sk-or-v1-ключ-второго-аккаунта
```

Нумерация начинается с 1 и идёт подряд. Имена должны быть уникальными.
Использовать чужие ключи и обходить лимиты провайдера нельзя — это нарушает
правила сервиса.

## Шаг 6. Скачайте проект и установите зависимости

### Куда скачивать

Выберите папку без пробелов и кириллицы в пути, например `C:\Bots`. Внутри
появится папка проекта `TG_2_Obsidian`.

### Вариант с Git (если Git установлен)

Откройте PowerShell и выполните:

```powershell
cd C:\Bots
git clone https://github.com/gZEVI-1/TG_2_Obsidian.git
cd TG_2_Obsidian
```

Если Git не установлен, скачайте ZIP: на странице репозитория нажмите
**Code → Download ZIP**, распакуйте и откройте терминал в получившейся папке.
Для распаковки ZIP команда `git` не нужна. Папка после распаковки может
называться `TG_2_Obsidian-main` — используйте её имя в команде `cd` или
переименуйте в `TG_2_Obsidian`.

### Windows

```powershell
cd C:\Bots\TG_2_Obsidian

python -m venv .venv
.\.venv\Scripts\Activate.ps1

python -m pip install --upgrade pip
pip install -r requirements.txt
```

Что это значит:

- `python -m venv .venv` создаёт отдельное окружение в папке `.venv`, чтобы
  зависимости не смешались с системными.
- `Activate.ps1` включает это окружение. В начале строки появится `(.venv)`.
- `pip install -r requirements.txt` ставит библиотеки проекта.

> ⚠️ Если PowerShell пишет, что «выполнение сценариев отключено», выполните
> один раз в этом же окне:
>
> ```powershell
> Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
> ```
>
> Затем снова активируйте окружение.

Если вы используете `cmd.exe` вместо PowerShell, активация выглядит так:

```bat
.venv\Scripts\activate.bat
```

### macOS и Linux

```bash
cd ~/Bots/TG_2_Obsidian

python3 -m venv .venv
source .venv/bin/activate

python -m pip install --upgrade pip
pip install -r requirements.txt
```

### RAG (необязательно)

Семантический поиск «по смыслу» требует отдельных зависимостей (в том числе
`torch`) и скачивает модель ~470 МБ:

```bash
pip install -r requirements-rag.txt
```

Если не хотите тратить место и время — пропустите. Бот будет искать по словам и
именам, этого достаточно для старта. Позже можно доустановить.

> ⚠️ Если `pip` не находит `torch` для вашей версии Python, поставьте Python
> 3.12 или 3.13 в отдельное окружение и повторите установку. Для базового бота
> RAG не нужен.

## Шаг 7. Заполните .env

`.env` — это текстовый файл с настройками и секретами. Он лежит **в корне
проекта**, рядом с папкой `app`, и никогда не попадает в Git.

### Создайте файл

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

macOS/Linux:

```bash
cp .env.example .env
```

Затем откройте `.env` любым текстовым редактором: Блокнот, Notepad++,
VS Code. **Не переименовывайте** его в `.env.txt`: в Windows включите показ
расширений (Проводник → вкладка «Вид» → «Расширения имён файлов»), чтобы
видеть настоящее имя.

### Пример A. Файловый режим и OpenRouter

Минимальный рабочий вариант. Замените значения на свои:

```ini
# --- Telegram ---
TELEGRAM_BOT_TOKEN=7123456789:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
# Кто может пользоваться ботом (свой id покажет @userinfobot)
TELEGRAM_ALLOWED_USERS=123456789

# --- LLM ---
LLM_STUB=false
LLM_MODELS=nvidia/nemotron-3-ultra-550b-a55b:free

LLM_API_1_NAME=main
LLM_API_1_BASE_URL=https://openrouter.ai/api/v1
LLM_API_1_KEY=sk-or-v1-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

# --- Obsidian: файловый режим ---
OBSIDIAN_MODE=vault
OBSIDIAN_VAULT_PATH=C:/Users/Анна/Documents/TG-OBS-Test

# --- Безопасность ---
OBSIDIAN_DRY_RUN=true

LOG_LEVEL=INFO
```

### Пример B. Local REST API

```ini
TELEGRAM_BOT_TOKEN=7123456789:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
TELEGRAM_ALLOWED_USERS=123456789

LLM_STUB=false
LLM_MODELS=nvidia/nemotron-3-ultra-550b-a55b:free
LLM_API_1_NAME=main
LLM_API_1_BASE_URL=https://openrouter.ai/api/v1
LLM_API_1_KEY=sk-or-v1-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

OBSIDIAN_MODE=rest
OBSIDIAN_BASE_URL=http://127.0.0.1:27123
OBSIDIAN_API_KEY=ключ-из-плагина-Local-REST-API

OBSIDIAN_DRY_RUN=true
LOG_LEVEL=INFO
```

### Пример C. Несколько аккаунтов LLM

```ini
TELEGRAM_BOT_TOKEN=7123456789:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
TELEGRAM_ALLOWED_USERS=123456789

LLM_STUB=false
LLM_MODELS=nvidia/nemotron-3-ultra-550b-a55b:free,deepseek/deepseek-r1:free,qwen/qwen3-235b-a22b:free

LLM_API_1_NAME=account-1
LLM_API_1_BASE_URL=https://openrouter.ai/api/v1
LLM_API_1_KEY=sk-or-v1-ключ-1

LLM_API_2_NAME=account-2
LLM_API_2_BASE_URL=https://openrouter.ai/api/v1
LLM_API_2_KEY=sk-or-v1-ключ-2

OBSIDIAN_MODE=vault
OBSIDIAN_VAULT_PATH=C:/Users/Анна/Documents/TG-OBS-Test
OBSIDIAN_DRY_RUN=true
```

`LLM_MODELS` — порядок качества: первая модель лучшая, дальше запасные. При
лимите на первой бот перейдёт ко второй, а не остановится.

### Правила для .env

- **Кодировка UTF-8**, без BOM. Если видите «кракозябры» в логах или путях —
  проверьте кодировку файла и консоли.
- **Не заключайте пути в кавычки без необходимости.** Кавычки нужны только
  если в значении есть `#` или пробелы в начале/конце.
- **Обратные слэши.** Можно писать `E:\Notes\MyVault` или
  `E:/Notes/MyVault`. Второй вариант безопаснее: не нужно думать об
  экранировании. Не заканчивайте путь обратным слэшем в кавычках.
- **Один параметр — одна строка.** Комментарии начинаются с `#`.
- **После любой правки `.env` перезапускайте бота**: настройки читаются один
  раз при старте.
- **Не коммитьте `.env`.** Он уже в `.gitignore`; не добавляйте его в Git
  вручную.

> 💡 Если не хотите пока вводить ключ LLM, можно поставить `LLM_STUB=true`.
> Бот запустится и будет отвечать «Заглушка LLM…», но **заметки создавать не
> сможет**: заглушка не вызывает инструменты. Это режим проверки настройки, а
> не рабочий режим.

## Шаг 8. Проверьте настройки

Выполняйте команды из папки проекта, при активированном `.venv` (в строке
должно быть `(.venv)`).

### 1. Настройки

```powershell
python -m app --check-config
```

Ожидается много строк лога и в конце:

```text
config OK
```

Если ошибка — она указывает на конкретную переменную. Исправьте `.env` и
повторите.

### 2. Хранилище

```powershell
python -m app --check-obsidian
```

Для файлового режима ожидается:

```text
Хранилище доступно напрямую: C:\Users\Анна\Documents\TG-OBS-Test (writable=True)
```

Для REST-режима:

```text
Local REST API доступен: ... (authenticated=True)
```

При `OBSIDIAN_DRY_RUN=true` дальше будет строка, что тестовая заметка не

> ⚠️ Если `OBSIDIAN_DRY_RUN=false`, проверка **создаст** в хранилище заметку
> `TG-OBS smoke test.md`. Её можно удалить.

### 3. Модель

```powershell

```

Ожидается ответ модели и строка о поддержке tool-calls:

```text
Модель ответила (...): ...
Tool-calls поддерживаются: get_weather(...)
```

Если вместо этого предупреждение «Модель не вызвала инструмент» — выбранная
модель не умеет function calling. Смените модель в `LLM_MODELS` на ту, у
которой есть поддержка tools.

### 4. RAG (только если установили)

```powershell
python -m app --check-rag
```

Первый запуск может занять несколько минут: скачивается модель. В конце —

```text
RAG-индекс: заметок N, фрагментов M, ...
```

Если RAG не установлен, эта команда сообщит об этом; на работу бота это не
влияет.

### 5. Готовность целиком

```powershell
python -m app --health
```

Одна проверка на все сразу: Telegram, хранилище, LLM, RAG, аудит, копии,
локальность адреса REST API, лог и dry-run. Нужно найти строку `health OK`.
Возможны два состояния:

```text
app.health: копии            warn  BACKUP_DIR не задан: команда --backup недоступна
```

Добавьте в `.env` папку для копий **вне хранилища** и повторите:

```ini
BACKUP_DIR=E:/TG-OBS/backups
BACKUP_KEEP=7
```

Подробности и разбор каждой строки — в
[13_health_backup.md](13_health_backup.md).

## Шаг 10. Создайте первую заметку

Сначала проверим безопасно: `OBSIDIAN_DRY_RUN=true`.

1. В Telegram нажмите **📖 Справка** или отправьте `/help`, чтобы увидеть
   кнопки.
2. Нажмите **📝 Новая заметка**.
3. Если в хранилище есть папка `Templates` с шаблонами, бот предложит выбрать
   шаблон. Для первой заметки выберите **Без шаблона**.
4. Отправьте текст:

   ```text
   Проверить, что бот подключён к хранилищу. Если я это вижу,
   значит всё работает.
   ```

5. Бот покажет превью («Предлагаю заметку… Куда сохранить?»). Выберите папку:
   **Inbox** (безопасный вариант) или **Автоопределение** — тогда бот
   предложит подходящие папки.
6. После выбора существующей папки бот сразу запишет заметку (при
   `AGENT_CONFIRMATION=auto`). Если папка новая или включён режим `always`,
   появится вопрос «Создать заметку …?» с кнопками **Подтвердить** и
   **Отмена**.
7. При dry-run бот ответит примерно так:

   ```text
   Dry-run: заметка «Inbox/...» не записана.
   ```

   Это успех проверки: бот всё понял, но запись запрещена настройкой.

Теперь разрешите реальную запись:

1. Откройте `.env` и замените `OBSIDIAN_DRY_RUN=true` на
   `OBSIDIAN_DRY_RUN=false`.
2. Остановите бота (`Ctrl+C`) и запустите снова: `python -m app`.
3. Повторите создание заметки. На этот раз в Obsidian появится файл.

Проверьте: откройте Obsidian, найдите заметку в `Inbox`. Если Obsidian был
закрыт — откройте хранилище, файл уже на месте.

> ⚠️ После выключения dry-run бот пишет по-настоящему. Убедитесь, что
> подключено **тестовое** хранилище, а не рабочее, пока не освоитесь.

## Шаг 11. Настройте свои промпты

«Промпты» — это тексты, которые определяют, как бот пишет и какие шаблоны
использует. Три уровня настройки:

### 1. Стиль письма — без кода

Создайте в Obsidian заметку, например `Templates/Мой стиль.md`, и опишите
словами, как вы пишете. Пример:

```markdown
# Мой стиль

- Пиши коротко: 2–4 предложения в абзаце.
- Тон спокойный, без канцелярита и без «Таким образом».
- В начале заметки — одна строка итога.
- Для задач используй чек-листы `- [ ]`.
- Даты — в формате ДД.ММ.ГГГГ.
- Не добавляй разделы, о которых я не просил.
- Не выдумывай факты: если чего-то нет, оставь пусто.
```

Затем в `.env`:

```ini
AGENT_STYLE_NOTE=Templates/Мой стиль.md
```

Перезапустите бота. В логе будет «Стиль пользователя загружен…». В промпт
попадают **первые 4000 символов** — важное пишите в начале.

### 2. Шаблоны заметок — без кода

Положите `.md`-файлы в папку `Templates` внутри хранилища (имя папки задаётся
`AGENT_TEMPLATE_FOLDER`). Бот покажет до шести шаблонов кнопками при создании.
Поддерживаются плейсхолдеры:

- `{{title}}` — заголовок заметки;
- `{{date}}` — дата `ГГГГ-ММ-ДД`;
- `{{date:DD.MM.YY}}` — дата в своём формате;
- `{{time}}`, `{{time:HH:mm:ss}}` — время.

Пример шаблона встречи:

```markdown
---
tags: [встреча]
date: {{date}}
---

# {{title}}

## Участники

## Повестка

## Решения

## Задачи
- [ ]
```

Templater-синтаксис (`<% ... %>`) бот не выполняет — используйте обычный
Markdown и плейсхолдеры выше.

### 3. Системный промпт — с правкой кода

Если нужно изменить сами правила поведения (тон, запреты, порядок действий),
они лежат в `app/agent.py`: `BASE_PROMPT`, `PARSE_RULES`, `WRITE_RULES`,
`STYLE_RULES`. Описания инструментов — в `app/actions.py`.

Это уже изменение кода: после `git pull` ваши правки могут конфликтовать.
Для большинства задач достаточно стиля и шаблонов.

**Подробное руководство с примерами и предупреждениями:**
[Свои промпты](PROMPTS.md).

## Шаг 12. Автозапуск и резервные копии (по желанию)

> ⚠️ Автозапуск на этом ПК **не нужен** и оставлен только для переноса на NAS
> (этап 12 отложен, ADR-44). Бот запускается вручную; если забыли — `--health`
> покажет, что его нет. Ниже — способ для случая, когда бот нужен постоянно.

### Резервные копии одной командой

```powershell
python -m app --backup
```

В `BACKUP_DIR` появится `tg-obs-backup-YYYYmmdd-HHMMSS.zip`: хранилище и
журнал `state/audit/`, без `.env` и `.obsidian` (в настройках плагина лежит
ключ API). Хранятся последние `BACKUP_KEEP` копий. Запускайте вручную раз в
день или поставьте в Планировщик заданий (как автозапуск ниже, только действие
— `python -m app --backup`). Восстановление и риски —
[13_health_backup.md](13_health_backup.md).

### Автозапуск при входе в систему

Бот должен работать постоянно. Можно запускать вручную, но удобнее — при
входе в систему.

### Windows

Создайте файл `start-bot.bat` в папке проекта:

```bat
@echo off
cd /d C:\Bots\TG_2_Obsidian
call .venv\Scripts\activate.bat
python -m app
pause
```

Проверьте, что двойной клик запускает бота. Затем:

1. Откройте **Планировщик заданий** (Task Scheduler).
2. **Создать задачу** (Create Task).
3. Вкладка **Триггеры** → **Создать** → «При входе в систему» (At log on).
4. Вкладка **Действия** → **Создать** → «Запуск программы» → выберите
   `start-bot.bat`.
5. Сохраните задачу.

Бот будет стартовать при входе в Windows. Окно консоли можно свернуть.

### Linux

Создайте unit-файл `/etc/systemd/system/tg-obs.service`:

```ini
[Unit]
Description=TG-OBS Telegram bot for Obsidian
Wants=network-online.target
After=network-online.target

[Service]
Type=simple
User=user
WorkingDirectory=/home/user/TG_2_Obsidian
ExecStart=/home/user/TG_2_Obsidian/.venv/bin/python -m app
Restart=on-failure
RestartSec=10
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
```

Замените путь и пользователя на свои, затем:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now tg-obs
sudo systemctl status tg-obs
```

Логи: `journalctl -u tg-obs -f`.

> ⚠️ Не запускайте два экземпляра одновременно: Telegram отдаст обновления
> только одному, второй получит ошибку `Conflict`. Перед запуском вручную
> остановите службу.

## Если что-то пошло не так

Сначала посмотрите на **последние строки лога** в терминале: там обычно
написана причина. Ниже — самые частые случаи.

| Симптом | Причина | Что делать |
|---|---|---|
| `python: команда не найдена` / открывается Microsoft Store | Python не в PATH | Переустановите с галочкой «Add python.exe to PATH» или используйте `py` |
| `Activate.ps1 cannot be loaded` | Политика выполнения PowerShell | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`, затем снова активируйте |
| `TELEGRAM_BOT_TOKEN не задан` | `.env` не найден или пустой токен | Файл должен лежать в корне проекта; проверьте, что он не `.env.txt`; перезапустите |
| Telegram: `Unauthorized` | Токен неверный или отозван | Получите новый у @BotFather и обновите `.env` |
| `Conflict: terminated by other getUpdates request` | Запущены два бота с одним токеном | Закройте лишний экземпляр, дождитесь остановки |
| Бот молчит в группе | Privacy mode у бота | Пишите в личный чат; для групп настройте бота в BotFather, но это не рекомендуется |
| `Не удалось связаться с Obsidian` | Режим `rest`, Obsidian закрыт или плагин выключен | Запустите Obsidian, включите Local REST API или перейдите на `OBSIDIAN_MODE=vault` |
| `Obsidian отклонил ключ` | `OBSIDIAN_API_KEY` не совпадает | Скопируйте ключ из настроек плагина заново |
| `Папка хранилища недоступна` | Опечатка в пути, нет прав, папка в облаке не скачана | Проверьте путь, права, скачайте папку локально |
| `OBSIDIAN_MODE=vault: задайте путь` | Пустой `OBSIDIAN_VAULT_PATH` | Укажите путь к корню хранилища |
| `LLM: модели заданы, а аккаунты нет` | Нет `LLM_API_1_*` | Заполните `LLM_API_1_BASE_URL` и `LLM_API_1_KEY` |
| `LLM: аккаунты заданы, а LLM_MODELS ... пуст` | Нет списка моделей | Заполните `LLM_MODELS` |
| `Модель отклонила ключ` | Неверный ключ или base URL | Проверьте ключ и адрес провайдера; для OpenRouter — `https://openrouter.ai/api/v1` |
| Бот отвечает «Заглушка LLM» | `LLM_STUB=true` | Поставьте `false`, заполните ключи и перезапустите |
| `У модели закончился лимит` | `429` у провайдера | Пул переключится сам; проверьте `/llm`, добавьте аккаунт или подождите |
| Модель отвечает, но заметки не создаёт | Модель не умеет tool-calls | Выберите модель с tools; проверьте `python -m app --check-llm` |
| `Dry-run: заметка ... не записана` | `OBSIDIAN_DRY_RUN=true` | Поставьте `false` и перезапустите |
| RAG: «нет зависимостей» / ошибка torch | Не установлен `requirements-rag.txt` или нет колеса для версии Python | `pip install -r requirements-rag.txt` или `RAG_ENABLED=false` |
| Написали боту, а он молчит | Вашего id нет в `TELEGRAM_ALLOWED_USERS` | Впишите id (узнать — @userinfobot) и перезапустите; отказ с id виден в `state/logs/app.log` |
| `--backup` отказывается: `BACKUP_DIR не задан` | Не задана папка для копий | `BACKUP_DIR=E:/TG-OBS/backups` в `.env`; папка должна быть **вне** хранилища |
| `--health` показывает `fail` | Сломано хранилище, LLM, аудит, лог или копии | Смотрите строку с `fail`: причина и путь написаны там же |
| В консоли «кракозябры» | Кодировка консоли | `chcp 65001` в cmd; в PowerShell — `$env:PYTHONIOENCODING='utf-8'` |
| Изменения в `.env` не применяются | Бот читает настройки при старте | Остановите и запустите заново |
| Ошибка `No module named app` | Команда запущена не из папки проекта | `cd` в папку, где лежат `app` и `.env` |

### Три самые частые причины

1. **`.env` лежит не там или называется `.env.txt`.** Проверьте: файл должен
   быть ровно `.env` в одной папке с `app`. Включите отображение расширений.
2. **`LLM_STUB=true`.** В этом режиме бот не использует ключи и не создаёт
   заметки. Для работы нужно `LLM_STUB=false` и заполненные `LLM_API_1_*`.
3. **Модель без tool-calls.** Бот «разговаривает», но не вызывает инструменты.
   Смотрите предупреждение в `--check-llm` и меняйте модель.

### Как собрать информацию для помощи

Если ошибка непонятная, скопируйте:

- последние 20–30 строк лога (без ключей и токенов!);
- вывод `python -m app --check-config`;
- версию Python (`python --version`);
- вашу ОС.

**Никогда не публикуйте** `.env`, токен бота и ключи LLM. В логах проекта
секреты маскируются, но текст ошибки сторонней библиотеки может содержать
лишнее.

## Безопасность и резервные копии

- **Токен Telegram** = управление ботом. Утёк — `/revoke` у @BotFather.
- **Ключ Obsidian** = доступ к хранилищу. Утёк — перегенерируйте в настройках
  плагина.
- **Ключ LLM** = деньги/лимиты. Утёк — удалите ключ в панели провайдера.
- **`.env` не коммитится.** Проверяйте `git status` перед коммитом.
- **Резервная копия хранилища.** Бот пишет аккуратно, но бэкап никто не
  отменял. Obsidian хранит удалённое в `.trash` (файловый режим) или в корзине
  приложения (REST), но это не заменяет резервную копию.
- **Приватность.** Внешняя LLM получает фрагменты заметок. Не держите в
  хранилище пароли и чужие персональные данные, если не готовы отправлять их
  провайдеру. Для чувствительных данных используйте локальную модель.
- **Кто может пользоваться.** Впишите свой числовой id в
  `TELEGRAM_ALLOWED_USERS` (узнать — бот **@userinfobot**). Пустой список
  означает «отвечать любому чату»; чужому бот молчит, а отказ пишется в лог
  с его id. Подробности — [14_access.md](14_access.md).
- **Резервная копия одной командой.** `python -m app --backup` кладёт zip
  хранилища и журнала в `BACKUP_DIR` без `.env` и `.obsidian`. Восстановление
  и ограничения — [13_health_backup.md](13_health_backup.md).
- **Проверка одним взглядом.** `python -m app --health` показывает, что
  сломано, если бот молчит или заметки не пишутся.
- **Тестовое хранилище.** Пока не освоились — работайте на копии, а не на
  основном хранилище.

## Если не хочется ставить Python (Docker)

Для NAS, VPS или чистого запуска есть образ: скопируйте `.env`, задайте
`VAULT_PATH` (путь к хранилищу на хосте) и выполните
`docker compose up -d --build`. Контейнер сам перезапускается после
перезагрузки, работает не от root и получает часовой пояс из `TZ`.
Подробности, обновление и RAG-сборка — [16_ci_docker.md](16_ci_docker.md).
