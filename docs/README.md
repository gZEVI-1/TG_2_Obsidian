# Документация TG-OBS

Telegram-бот с AI-агентом для Obsidian: создаёт и правит заметки в вашем стиле,
ставит связи, ищет по смыслу и работает как через Local REST API, так и
напрямую с `.md`-файлами. Здесь — карта документации: что читать, если вы
только ставите бота, что — если настраиваете под себя, и что — если хотите
понять, как он устроен.

## Начните здесь

| Если вы… | Начните с |

## Разработка

- [STAGES.md](STAGES.md) — все этапы 0–15: что сделано, в каком файле,
  текущий статус. Этап 12 (NAS) — опциональная инфраструктура.
- [DECISIONS.md](DECISIONS.md) — журнал архитектурных решений ADR-01…ADR-49:
  контекст, решение, последствия.
- [README.md → «Разработка и тесты»](../README.md#разработка-и-тесты) —
  команды тестов, `--check-*`, как добавить новую команду агенту.
- [ABOUT.md](ABOUT.md) — готовый текст для поля About на GitHub, topics и
  короткое описание для каталогов.
- `tests/` — 252 теста на `unittest`, без сети и без секретов; CI гоняет их
  на Python 3.11/3.12/3.13.

## Как устроена папка

`docs/` — не только справочники. По одному файлу на этап: `00_…`—`16_…`.
В каждом — цель, что сделано, внешние действия, принятые решения, как
проверить и как откатить. Номера файлов не всегда совпадают с номером этапа
(файлы появлялись по мере роста документации) — точное соответствие в
[STAGES.md](STAGES.md).

Секретов и токенов в документации нет: только имена переменных и
плейсхолдеры.
