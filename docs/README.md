# Документация проекта TG-OBS

Telegram-бот с AI-агентом для Obsidian: через Local REST API или напрямую
с файлами хранилища.
Целевые возможности: создание заметок по шаблону или в моём стиле, небольшая
генерация текста, добавление и правка существующих заметок, автоматическое
расположение внутри хранилища, простановка связей и обработка ошибок API.
Подробные требования — в [FEATURES.md](FEATURES.md).

## Целевые функции

Подробности и критерии приёмки — в [FEATURES.md](FEATURES.md). Кратко:

- создание новой заметки;
- добавление в существующую заметку с поиском по контексту (полнотекстовый
  поиск до внедрения RAG);
- изменение существующей заметки: добавление и правка выбранного раздела,
  без полной перезаписи;
- создание разделов, работа с папками, копирование, перенос и удаление заметок
  (см. [09_manage.md](09_manage.md));
- автоматическое расположение заметки: кнопки «Inbox» и «Автоопределение»,
  с уточнением при неоднозначности;
- автопростановка связей при создании и изменении;
- простановка связей во всех заметках с подтверждением;
- общая настройка необходимости подтверждений (`auto` / `always` / `never`);
- обработка ошибок API и сервера без падения бота, потери данных и дублей.

## Текущее состояние

Готовы этапы 7, 8 и управление заметками. Бот на `aiogram 3.x` запускается
командой `python -m app`,
помнит контекст диалога (`/new` и `/start` начинают новый), ищет и читает
заметки, создаёт новые с подсказками папок (включая новую — с подтверждением
создания), дописывает текст в подходящий раздел и правит разделы.
Модель — OpenRouter, `nvidia/nemotron-3-ultra-550b-a55b:free`.

LLM работает через пул аккаунтов и моделей: при лимите на аккаунте запрос
уходит на следующий аккаунт той же модели, после всех аккаунтов — на
следующую модель по качеству, а после исчерпания всех пар срабатывает
автосброс к лучшей модели. Пока реальные ключи не добавлены, включён режим
заглушек. Подробности и переменные — [LLM_POOL.md](LLM_POOL.md).

Агент работает по FR-01…FR-04, FR-07…FR-09 ([FEATURES.md](FEATURES.md)):
подтверждения по `AGENT_CONFIRMATION`, расположение по кнопкам
«Inbox» / «Автоопределение» / «Другая папка», полнотекстовый поиск, правка
разделов через read-modify-write, классификация ошибок API. Запись
по умолчанию заблокирована dry-run.

Связи (FR-05, FR-06, FR-10) — готовы: при создании и правке бот предлагает
ссылки на существующие заметки (кнопкой «Добавить связи»), ставит их
в раздел «Связи» и не дублирует уже имеющиеся. Кнопка «🔗 Связи во всех
заметках» и `/links` строят план по всему хранилищу и проставляют связи
после подтверждения. Подробности — [08_links.md](08_links.md).

Шаблоны и стиль — готовы: шаблоны
берутся из `AGENT_TEMPLATE_FOLDER` (по умолчанию `Templates`), выбор — кнопкой
при создании (до шести шаблонов); стиль — заметка из `AGENT_STYLE_NOTE`.
Пять шаблонов из рабочего хранилища адаптированы под бота (Templater вырезан) и
лежат в `templates/` — папка в `.gitignore`, копии переносятся в vault.
Подробности — [07_templates_style.md](07_templates_style.md).

Разделы, папки и операции с заметками — готовы: «создай раздел», «создай /
переименуй / удали папку», «перемести / скопируй / удали заметку», «удали из
заметки строку/ссылку/абзац». Опасные операции идут через превью и
подтверждение. Подробности — [09_manage.md](09_manage.md).

Семантический поиск (RAG) — готов: локальные эмбеддинги
(`sentence-transformers`) находят заметки по смыслу, когда точных слов нет.
Индекс строится в фоне и обновляется по `/reindex`; без RAG-зависимостей бот
работает как раньше. Подробности — [10_rag.md](10_rag.md).

Хранилище можно подключить двумя способами. По умолчанию — Local REST API
(Obsidian должен быть запущен). Если задать `OBSIDIAN_MODE=vault` и
`OBSIDIAN_VAULT_PATH`, бот читает и пишет `.md`-файлы напрямую, и Obsidian
может быть закрыт. Подробности — [06_vault_mode.md](06_vault_mode.md).

Внизу чата — две страницы кнопок: главная («Остаться в этом чате»,
«Новый диалог», «Начать заново», «Справка») и сценарии заметок
(«Новая заметка», «Дописать», «Править раздел», «Найти», «Связи во всех
заметках», «Назад»).

Служебные команды:

```powershell
.\.venv\Scripts\python.exe -m app --check-config     # настройки, без сети
.\.venv\Scripts\python.exe -m app --check-obsidian   # Local REST API + тестовая запись
.\.venv\Scripts\python.exe -m app --check-llm        # модель + поддержка tool-calls
.\.venv\Scripts\python.exe -m app --check-rag        # эмбеддинги, индекс и пробный поиск
```

В Telegram: `/llm` — состояние пула и лимитов, `/llm_reset` — ручной сброс
к начальным условиям, `/links` — связи во всех заметках, `/rag` — состояние
семантического поиска, `/reindex` — пересобрать индекс.

## Смежные папки

- `.env` — реальные секреты, в git не попадает.
- `templates/` — личные адаптированные шаблоны и описание стиля; в `.gitignore`,
  в репозиторий не попадает.
- `state/rag/` — локальный индекс семантического поиска; производный кэш,
  в `.gitignore`, удаляется без последствий.
- `E:\FOLDER\TG-OBS\TG-OBS-vault-test` — тестовое хранилище Obsidian
  с плагином Local REST API (HTTP, порт 27123). Рабочий vault не используется.
