# Этап 2: Скелет Telegram-бота

## Этап

Этап 2 — минимальный Telegram-бот на `aiogram 3.x`: запуск через long polling,
команды `/start` и `/help`, эхо на текст.

## Цель

Довести проект до состояния «бот в Telegram отвечает». Никакой LLM и Obsidian
здесь ещё нет: важно убедиться, что цикл запуска, конфигурация и обработчики
работают, прежде чем добавлять интеллект.

## Что сделано

- `requirements.txt` — добавлен `aiogram>=3.13,<4`. Фактически установлено:
  aiogram 3.31.0, pydantic 2.13.5, aiohttp 3.14.5 (на Python 3.14.4 всё
  встало из готовых сборок, компиляция не потребовалась).
- `app/bot.py`:
  - `router` — корневой `Router` с обработчиками;
  - `cmd_start()` — `/start`, приветствие и объяснение текущих возможностей;
  - `cmd_help()` — `/help`, список команд;
  - `echo_text()` — повторяет любой текст;
  - `fallback()` — на не-текст (фото, стикеры) отвечает «понимаю только текст»;
  - `run_bot()` — создаёт `Bot` и `Dispatcher`, логирует `@username` из `get_me()`,
    снимает возможный webhook, запускает `start_polling()`, в `finally`
    закрывает сессию.
- `app/__main__.py`:
  - `--check-config` — проверка настроек без запуска бота (печатает `config OK`);
  - проверка `TELEGRAM_BOT_TOKEN` перед запуском: если пусто — понятная ошибка
    в лог и `exit code 2`, вместо падения внутри aiogram;
  - `log_settings()` — безопасная сводка настроек, перенесена из прежнего `main()`.

## Внешние действия

Требуется от пользователя:

1. `@BotFather` → `/newbot` → имя и username → скопировать токен.
2. Вписать в `E:\FOLDER\TG-OBS\TG_2_Obsidian\.env` строку
   `TELEGRAM_BOT_TOKEN=<токен>`. Токен в чат не отправлять.
3. Запустить бота и написать ему `/start`.

Результат: токен принят, `get_me()` вернул бота `@tg2Obs_gZEVI_bot`. Живой
ответ на `/start` подтверждён пользователем перед переходом к Этапу 3.

## Принятые решения

- **Long polling, а не webhook.** ПК за домашним NAT без публичного адреса и
  сертификата; polling не требует входящих соединений. При переносе на NAS
  решение можно пересмотреть (ADR-09).
- **`--check-config` вместо печати `config OK` при каждом запуске.** Иначе
  проверка из Этапа 1 перестала бы работать: обычный запуск теперь поднимает
  бота.
- **Проверка токена до создания `Bot`.** Ошибка «забыл токен» должна быть
  понятной строкой в логе, а не трейсбеком aiogram.
- **`delete_webhook(drop_pending_updates=True)`.** Защита от «залипших»
  сообщений и конфликта, если для токена когда-то был настроен webhook.
- **Эхо оставлено намеренно.** Это временный обработчик: на Этапе 5 его место
  займёт вызов агента. Пока он даёт бесплатный способ проверить, что бот жив.
- **Хранилище состояний по умолчанию (`MemoryStorage`).** Диалоги в памяти
  процесса; для одного пользователя этого достаточно, Redis не вводим.

## Как проверить

```powershell
cd E:\FOLDER\TG-OBS\TG_2_Obsidian

# 1. Конфигурация без запуска бота
.\.venv\Scripts\python.exe -m app --check-config     # -> config OK

# 2. Запуск бота (нужен токен в .env)
.\.venv\Scripts\python.exe -m app
```

Ожидается:

- в логе `Бот @<username> запущен, ожидаю сообщения`;
- в Telegram `/start` и `/help` отвечают текстом, любой текст возвращается
  эхом, фото/стикер — «Пока я понимаю только текст»;
- остановка по `Ctrl+C` пишет `Бот остановлен` и завершается без трейсбека.

Без токена:

```powershell
.\.venv\Scripts\python.exe -m app
# ERROR app: TELEGRAM_BOT_TOKEN не задан: впишите токен от @BotFather в .env
# exit code 2
```

## Риски и откат

- Риск: токен попадёт в git или в лог. Токен читается только из `.env`
  (в `.gitignore`), в логи не выводится.
- Риск: два процесса polling с одним токеном конфликтуют (`409 Conflict`).
  Держать запущенным только один экземпляр.
- Риск: бот отвечает посторонним. Ограничения по `chat_id` появятся на
  Этапе 9; сейчас бот публичный для всех, кто знает его username.
- Откат: убрать `app/bot.py`, вернуть прежний `app/__main__.py` (без `bot`),
  удалить `aiogram` из `requirements.txt` и venv. Данные vault не затрагиваются.
