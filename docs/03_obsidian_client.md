# Этап 3: Клиент Obsidian Local REST API

## Этап

Этап 3 — асинхронный клиент Obsidian Local REST API: проверка соединения, чтение
заметки, запись заметки с защитой от перезаписи, режим dry-run.

## Цель

Научиться безопасно общаться с хранилищем до того, как к нему получит доступ
LLM. Проверки идут только на тестовом vault `TG-OBS-vault-test`.

## Что сделано

- `app/obsidian.py`:
  - `ObsidianError` — единый тип ошибок клиента;
  - `ObsidianClient` — клиент на `aiohttp` с одной сессией на время жизни,
    `Authorization: Bearer <ключ>`, таймаут 10 секунд;
  - `health()` — `GET /`: проверка доступности API и валидности ключа;
  - `note_exists()` — `GET /vault/{path}` с `Accept: application/json`;
    `404` → `False`;
  - `read_note()` — `GET /vault/{path}` с `Accept: text/markdown`;
  - `write_note(path, content, overwrite=False)` — `PUT /vault/{path}`.
    Возвращает `True`, если файл реально записан; в dry-run возвращает `False`
    и ничего не отправляет в Obsidian;
  - имена файлов кодируются через `quote(..., safe='/')`, чтобы работали
    кириллические имена и вложенные папки;
  - пустой `OBSIDIAN_API_KEY` → `ObsidianError` при создании клиента.
- `app/__main__.py`:
  - флаг `--check-obsidian` (взаимоисключающий с `--check-config`):
    проверяет API и пытается создать тестовую заметку `TG-OBS smoke test.md`;
    запись вызывается с `overwrite=True` — это проверочная акция, и повторный
    запуск не должен падать на защите от перезаписи;
  - понятные ошибки: `ObsidianError` и `aiohttp.ClientError` (последняя —
    «проверьте, что Obsidian запущен и сервер включён»), выход с кодом 2.
- `requirements.txt` — добавлен `aiohttp>=3.9,<4` (приходил транзитивно с
  aiogram, но теперь используется напрямую — должен быть объявлен явно).

## Внешние действия

Не требовались: тестовый vault, плагин Local REST API и ключ были готовы после
Этапа 1. Obsidian должен быть запущен с открытым тестовым vault — на момент
проверки так и было.

## Принятые решения

- **`aiohttp`, а не `requests`.** Бот и агент асинхронные; блокирующий HTTP-клиент
  остановил бы обработку апдейтов Telegram (ADR-11).
- **`write_note(overwrite=False)` по умолчанию.** Файл с таким именем — ошибка, а
  не молчаливая замена чужой заметки. Перезапись возможна только явным флагом
  (ADR-10).
- **Dry-run блокирует запись до обращения к API.** В этом режиме клиент даже не
  проверяет существование файла: ни одного изменяющего запроса в vault.
- **Одна `ClientSession` на клиент.** Создание сессии на каждый запрос дороже и
  приводит к утечкам, если её забыть закрыть.
- **Никаких ретраев.** Пока неясно, какие ошибки реально встречаются; ретраи без
  данных — источник дублей заметок. Вернёмся на Этапе 9, если понадобится.
- **Флаг CLI вместо отдельного скрипта.** `python -m app --check-obsidian` — одна
  команда, которая всегда под рукой и не требует помнить путь к утилите.

## Как проверить

```powershell
cd E:\FOLDER\TG-OBS\TG_2_Obsidian

# 1. Dry-run (в .env OBSIDIAN_DRY_RUN=true): API отвечает, запись пропускается
.\.venv\Scripts\python.exe -m app --check-obsidian

# 2. Реальная запись в тестовый vault — только тестовое хранилище!
$env:OBSIDIAN_DRY_RUN='false'
.\.venv\Scripts\python.exe -m app --check-obsidian
```

Ожидается в первом случае:

```
INFO app: Local REST API доступен: Obsidian Local REST API (authenticated=True)
INFO app.obsidian: [dry-run] запись заметки TG-OBS smoke test.md (103 симв.) пропущена
INFO app: Заметка не записана: включён dry-run. ...
```

во втором:

```
INFO app.obsidian: Заметка записана: TG-OBS smoke test.md
INFO app: Тестовая заметка записана: TG-OBS smoke test.md
```

и в Obsidian появляется заметка `TG-OBS smoke test.md`. Признак успеха в обоих
случаях — `authenticated=True`; `HTTP 401` означает неверный ключ.

Проверки, выполненные на этапе: `health()`, реальная запись, чтение
(103 символа), `note_exists()`, защита от перезаписи, `404` на
несуществующую заметку.

## Риски и откат

- Риск: запись не в тот vault. Проверяется глазами по имени хранилища в заголовке
  окна Obsidian; `OBSIDIAN_BASE_URL` указывает на 127.0.0.1:27123 тестового
  vault. Рабочий vault на этом этапе не подключён.
- Риск: ключ попадёт в лог. Ключ не логируется, в сводке только `<задан, 64 симв.>`.
- Риск: HTTP вместо HTTPS. Плагин включён в незашифрованном режиме; трафик не
  покидает машину. При переносе на NAS — только HTTPS или туннель.
- Откат: заметка `TG-OBS smoke test.md` удаляется в Obsidian вручную. Код
  откатывается удалением `app/obsidian.py` и флага `--check-obsidian`.
  Рабочие заметки не затрагивались.
