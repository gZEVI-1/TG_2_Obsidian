# Этап 13: доступ по списку Telegram-пользователей

## Этап

Этап 13 — ограничение доступа: бот должен отвечать только владельцу (и тем,
кого он впишет), а не любому чату. Закрывает последнюю незакрытую
функциональную брешь из [INSTALL.md](INSTALL.md); этап 12 (NAS) отложен
по ADR-44.

## Цель

Сделать так, чтобы:

- чужой человек, узнавший username бота, не мог читать и менять хранилище;
- отказ не подтверждал, что бот жив, и не превращался в переписку;
- попытка доступа была видна в логе вместе с id — его можно скопировать
  в настройку;
- `--health` показывал, под каким ботом работает токен и сколько людей
  допущено.

## Что сделано

- `app/access.py` — `AllowedUsersMiddleware` (aiogram `BaseMiddleware`):
  берёт `event_from_user` из данных события, пускает id из списка, остальным
  не отвечает и пишет в лог `Отказ в доступе: id=…, username=…`.
  Пустой список означает «пускать всех» — так прежние `.env` продолжают
  работать, но при старте выводится предупреждение.
- `app/config.py` — `TELEGRAM_ALLOWED_USERS` → `Settings.telegram_allowed_users`
  (кортеж `int`), разбор через запятую и/или пробел, дубликаты убираются,
  нечисловые и неположительные значения — понятная ошибка при старте;
  в `safe_summary()` попадает количество разрешённых, а не сами id.
- `app/bot.py` — в `run_bot()` middleware ставится на `dispatcher.message` и
  `dispatcher.callback_query` (outer), поэтому покрывает команды, кнопки,
  текстовые сообщения и callback-и, включая будущие обработчики; в лог
  пишется «разрешённых пользователей — N» или предупреждение, что список пуст.
- `app/health.py` — проверка `Telegram`: `getMe` подтверждает токен, строка
  показывает `@username` и число разрешённых; пустой список — `warn`
  «отвечает любому чату», отозванный токен или недоступная сеть — `fail`.
- `tests/test_access.py` — 11 тестов: пропуск своего, молчаливый отказ чужому,
  пустой список, событие без пользователя, регистрация на сообщения и
  callback-и, разбор `TELEGRAM_ALLOWED_USERS` (запятые, пробелы, дубликаты,
  пусто, мусор, `0` и отрицательные).

## Внешние действия

1. Узнать свой числовой id: написать боту **@userinfobot** — он ответит
   строкой `Id: 123456789`. Подойдёт и любой другой способ узнать id.
2. Вписать в `.env`:

   ```dotenv
   TELEGRAM_ALLOWED_USERS=123456789
   ```

   Несколько человек — через запятую: `123456789, 987654321`.
3. Перезапустить бота и проверить: `--health` покажет
   `Telegram ok @…: разрешено 1`.

Пока список пуст, бот по-прежнему открыт — это сделано для того, чтобы
обновление не заблокировало вас на первом запуске.

## Принятые решения

- **Только числовые id, без username.** Username можно сменить или не иметь
  вовсе; id стабилен и не угадывается. Цена: id нужно узнать один раз.
- **Пустой список — «пускать всех», а не «закрыть всё».** Иначе после
  обновления бот молча перестал бы отвечать владельцу, который ещё не вписал
  id. Предупреждение в логе и `warn` в `--health` напоминают закрыть доступ.
- **Молчание вместо отказа.** Ответ «доступ запрещён» подтверждает
  существование бота и приглашает к перебору; молчание этого не делает и не
  даёт флуду превращаться в диалог. Id отказавшегося всё равно попадает в лог.
- **Middleware на диспетчере, а не фильтр на каждом обработчике.**
  Обработчиков больше сорока; забыть фильтр на новом — типичная ошибка.
  Один middleware покрывает все текущие и будущие события этого типа.
- **Callback-и закрыты отдельно.** Нажатие кнопки — не сообщение; без второго
  `outer_middleware` чужой мог бы нажимать кнопки в старом сообщении.
- Отклонено: список в коде (нельзя поменять без правки репозитория) и
  проверка в `answer_text` (остальные команды остались бы открыты).

```powershell
cd E:\FOLDER\TG-OBS\TG_2_Obsidian
.\.venv\Scripts\python.exe -m unittest discover -s tests    # на момент этапа 216 тестов, OK (сейчас 237)
.\.venv\Scripts\python.exe -m app --health
```

Ожидаемые строки (проверено 30.10.2026):

```
app.health: Telegram         ok    @tg2Obs_gZEVI_bot: разрешено 1
```

Пока список пуст — `warn @…: TELEGRAM_ALLOWED_USERS не задан — отвечает любому чату`.

Проверка отказа: написать боту с другого аккаунта. Ответа нет, в логе
(`state/logs/app.log`):

```
app.access: Отказ в доступе: id=…, username=…. Добавьте id в TELEGRAM_ALLOWED_USERS.
```

Проверка доступа: свой аккаунт получает обычный ответ на `/start`.

## Риски и откат

- **Опечатка в id** = бот молчит для вас. Исправляется в `.env` и перезапуском;
  заблокировать себя насмерть нельзя, файл всегда под рукой.
- **Смена аккаунта** — добавьте новый id; старый можно оставить или убрать.
- **Общий чат.** Ограничение по id пользователя, а не по чату: если написать
  боту в группе, отвечать он будет только разрешённым, но включение
  групповых чатов не проверялось.
- **Список в памяти.** Изменения в `.env` применяются после перезапуска бота,
  «на горячую» не подхватываются.
- **Откат.** Убрать `TELEGRAM_ALLOWED_USERS` из `.env` — бот снова открыт для
  всех (не рекомендуется); код — возврат `app/access.py`, `app/bot.py`,
  `app/config.py`, `app/health.py`.
