# Пул LLM: ротация аккаунтов, моделей и автосброс

Документ описывает `LLMPool` (`app/llm.py`) — слой между агентом и
OpenAI-совместимыми API. Пул нужен, чтобы бот продолжал отвечать, когда у
одного аккаунта закончилась квота, а затем и когда закончились все модели.

## Модель данных

- **Модели** — упорядоченный по качеству список `LLM_MODELS`: первая лучшая,
  последняя самая слабая/дешёвая.
- **Аккаунты** — независимые API-ключи `LLM_API_<N>_*` (разные аккаунты
  одного или разных провайдеров).
- **Пара** — конкретная комбинация «модель — аккаунт». Лимит считается по
  паре: у одного аккаунта на разных моделях разные квоты.

## Алгоритм

1. Запрос идёт на лучшую модель и первый доступный аккаунт.
2. Ответ `429`/`402` помечает пару исчерпанной до `Retry-After` (или
   `LLM_COOLDOWN_SECONDS`, если заголовка нет) и запрос повторяется на
   следующем аккаунте **той же модели**.
3. Когда кончились все аккаунты модели, пул переходит к следующей модели и
   снова начинает с первого аккаунта.
4. Когда исчерпаны все пары, пул запоминает ближайшее время освобождения
   (`reset_at`) и отвечает `LLMAllExhaustedError`. Новые запросы ждут.
5. В момент `reset_at` автосброс возвращает всё к начальным условиям:
   лучшая модель, первый аккаунт, все лимиты сняты.
6. `401`/`403` отключает аккаунт целиком до автосброса/ручного сброса:
   неверный ключ не лечится сменой модели.

Фоновая задача автосброса запускается в `run_bot()` через
`pool.start_auto_reset()` и проверяет состояние каждые 5 секунд. Ручной сброс
доступен командой `/llm_reset`.

## Режим заглушек

Пока реальные ключи не добавлены, включён `LLM_STUB=true`:

- сеть не используется, `LLM_API_*KEY` можно не заполнять;
- создаются аккаунты `stub-1…stub-N` (`LLM_STUB_ACCOUNTS`);
- у каждой пары своя квота `LLM_STUB_QUOTA`; после неё заглушка отвечает
  `429`, как настоящий провайдер;
- через `LLM_STUB_RESET_SECONDS` квоты и пул сбрасываются;
- в ответе видно `модель`, `аккаунт` и пометку «Заглушка LLM».

Этого достаточно, чтобы проверить ротацию и автосброс, не тратя лимиты.
Переход на реальные API: заполнить `LLM_API_1_*`, `LLM_API_2_*`, … и
поставить `LLM_STUB=false`.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `LLM_STUB` | режим заглушек | `false` |
| `LLM_STUB_ACCOUNTS` | число заглушек | `3` |
| `LLM_STUB_QUOTA` | запросов на пару до `429` | `2` |
| `LLM_STUB_RESET_SECONDS` | сброс квот заглушек | `60` |
| `LLM_MODELS` | модели через запятую, от лучшей к худшей | — |
| `LLM_API_<N>_NAME` | имя аккаунта для `/llm` | `account-N` |
| `LLM_API_<N>_BASE_URL` | base URL провайдера | — |
| `LLM_API_<N>_KEY` | ключ аккаунта | — |
| `LLM_COOLDOWN_SECONDS` | пауза пары при `429` без `Retry-After` | `3600` |

Старые `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` работают как один
аккаунт и одна модель, если `LLM_API_*` / `LLM_MODELS` не заданы.

## Команды

- `/llm` — активная модель и аккаунт, доступные пары, список лимитов и время
  автосброса.
- `/llm_reset` — снять все лимиты и вернуться к лучшей модели/первому
  аккаунту.

## Проверка

```powershell
cd E:\FOLDER\TG-OBS\TG_2_Obsidian
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -B -m app --check-llm
```

Тесты покрывают: ротацию аккаунтов внутри модели, переход к следующей модели,
исчерпание всех пар, автосброс к лучшей модели, отключение аккаунта с
неверным ключом, работу заглушек и разбор настроек.
