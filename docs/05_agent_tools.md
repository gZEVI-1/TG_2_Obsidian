# Этап 5: Агент с инструментами

## Этап

Этап 5 — агент, который работает с хранилищем: создаёт заметки, дописывает и
правит разделы, раскладывает по папкам, ищет по контексту и обрабатывает ошибки
API. Реализует FR-01…FR-04, FR-07…FR-09 из [FEATURES.md](FEATURES.md).

## Цель

Превратить «чат с моделью» в агента с ограниченным набором инструментов, где
любая запись проходит через понятный пользователю выбор и подтверждение, а
ошибки не приводят к молчаливой потере данных.

## Что сделано

- `app/config.py` — настройки агента с валидацией при загрузке:
  - `AGENT_CONFIRMATION` (`auto` / `always` / `never`, по умолчанию `auto`);
  - `AGENT_DEFAULT_FOLDER` (по умолчанию `Inbox`);
  - `AGENT_AUTO_FOLDER` (`true` — показывать «Автоопределение»);
  - `AGENT_SEARCH_LIMIT` (1–20, по умолчанию 5).
  Неверное значение → `ValueError` с объяснением, а не молчаливая подстановка.
- `app/obsidian.py`:
  - `ObsidianError` получил `status` — код ответа для классификации ошибок
    (FR-08);
  - `search_notes(query, limit)` — поиск по именам и содержимому: точное имя
    файла, имя с этого слова, имя, содержащее слово, похожие имена (опечатки,
    другой порядок слов — `difflib` по имени и сегментам пути), и только потом
    `POST /search/simple/`. Штатный поиск Obsidian ранжирует по тексту и
    ссылкам, из-за чего заметка «Мария» оказывалась ниже чужих упоминаний;
  - `app/search.py` — чистое ранжирование имён: нормализация (регистр, «ё»,
    пунктуация), оценки 1.0 / 0.95 / 0.9 / 0.85 / 0.8, нечёткое сходство
    с порогом 0.78;
  - `search(query, limit)` — «сырой» полнотекстовый поиск, используется как
    второй шаг;
  - `list_notes()` — рекурсивный обход `GET /vault/` до 3 уровней и 500 файлов;
  - все ошибки несут HTTP-код.
- `app/notes.py` — чистые функции без сети:
  - `slugify()` — заголовок в имя файла: запрещённые символы `\ / : * ? " < > |
    # ^ [ ]`, схлопывание пробелов, обрезка до 80 символов;
  - `build_path(folder, title)` — путь с учётом вложенности;
  - `validate_path()` — отказ на пустом пути, `..`, пустых сегментах,
    запрещённых символах, длине > 200 символов, отсутствии `.md`;
  - `find_section()` / `replace_section()` / `append_to_section()` — работа с
    разделами Markdown: заголовок ищется без учёта регистра и решёток, тело
    раздела — до следующего заголовка того же или более высокого уровня;
    frontmatter и остальные разделы сохраняются; дубль заголовка — ошибка;
  - `append_to_note()` — блок в конец заметки.
- `app/agent.py` — цикл инструментов:
  - `app/actions.py` — реестр команд: каждая `Action` хранит имя, заголовок,
    подсказку, JSON-схему и признак `writes`. Из реестра собираются и список
    инструментов для модели, и блок промпта — новая команда появляется в обоих
    местах автоматически;
  - `SYSTEM_PROMPT` — базовый тон + сгенерированный список команд + правила
    разбора («что / где / какой текст», контекст диалога, выбор команды по
    смыслу) + правила письма;
  - **модель всегда сама определяет команду**: кнопки лишь задают её заранее,
    но текст всё равно проходит через модель;
  - `clarify(question)` — команда-уточнение: если запрос не похож ни на одну
    команду или неясно место, модель задаёт вопрос, а бот показывает его
    вместе с кнопками действий;
  - `compose_note()` / `compose_append()` / `compose_section()` — обязательная
    переработка текста: сообщение переписывается под заметку (заголовок,
    структура, формат раздела) и не вставляется дословно;
  - `Proposal` — предложенное изменение (`create` / `append` / `section`);
  - `Agent.handle()` — до 6 шагов; читающие инструменты выполняются и их
    результаты возвращаются модели, изменяющий инструмент завершает ход;
  - `Agent.suggest_folders()` — до трёх папок-кандидатов для FR-04;
  - ошибки инструментов уходят модели текстом («заметка не найдена»), а не
    падают наружу; длинная заметка обрезается до 4000 символов.
- `app/bot.py` — сценарии и состояние:
  - `ChatMemory` хранит историю (20 сообщений) и ожидающее действие с
    `message_id` сообщения с кнопками;
  - создание: превью → кнопки «Inbox» / «Автоопределение» / «Другая папка» →
    проверка существования пути → (подтверждение) → запись;
  - при совпадении имени предлагается «Дописать» в существующую заметку или
    отмена — молчаливой перезаписи нет;
  - дописывание и правка раздела: превью → подтверждение (в `auto` для правок
    всегда) → read-modify-write;
  - дописывание идёт **в выбранный по смыслу раздел** (`append_to_section`),
    в конец — только если подходящего раздела нет; элемент списка приклеивается
    к списку без пустой строки, проза отделяется абзацем;
  - дубликат не пишется: если текст уже есть в заметке (`contains_text`,
    без учёта регистра и пробелов), бот отвечает «такой текст уже есть»;
  - «Автоопределение» при недоступной модели не падает: показывает папки,
    подобранные по названию, либо просто список папок хранилища, и честно
    пишет, что модель недоступна;
  - «Другая папка» — следующий текст пользователя трактуется как папка
    (поддерживается вложенность `Проекты/2026`);
  - кнопки привязаны к сообщению: повторное нажатие и устаревшие кнопки дают
    «это предложение устарело» и ничего не пишут;
  - reply-клавиатура из двух страниц: главная — «Остаться в этом чате»,
    «Новый диалог», «Начать заново», «Справка»; страница сценариев —
    «Новая заметка», «Дописать», «Править раздел», «Найти», «Назад»;
    «Справка» не переключает страницу, остальные кнопки главной ведут
    к сценариям, «Назад» возвращает на главную и отменяет незавершённый
    сценарий;
  - кнопки заметок запускают пошаговый сценарий без участия модели: кнопка
    задаёт режим, дальше бот спрашивает только недостающее (текст, заметку,
    раздел) и в конце показывает обычное подтверждение. Поиск заметки —
    `search/simple`, список разделов — из заголовков уровня 2 и глубже,
    поэтому заголовок-название заметки разделом не считается;
  - текст кнопок команд сравнивается с константой точно, поэтому нажатие
    выполняет команду, не попадая к модели; те же три команды зарегистрированы
    в меню Telegram (`set_my_commands`);
  - ошибки классифицируются: `401/403` — ключ, `404` — не найдено, `409` —
    занято, `429` — лимит, `5xx` — сервер, сеть — «проверьте, что Obsidian
    запущен».
- `docs/` — этот файл, обновлённые `README.md` и `DECISIONS.md`.

### Правка после Этапа 7 (по итогам ручного прогона)

Пользователь создавал карточку человека: модель предложила заголовок
`Люди/101 Александр Шевчук`, но бот показал только «Inbox / Автоопределение /
Другая папка», а ответ «Создай папку люди и добавь туда» ушёл в модель и она
повторила то же предложение.

- `app/notes.py` — новые чистые функции:
  - `clean_folder(name)` — безопасный путь папки: сегменты через `slugify`,
    `..` и `.` отбрасываются;
  - `folder_from_text(text, folders)` — название папки из ответа:
    «Создай папку люди и добавь туда» → «Люди» (с сохранением написания
    существующей папки), «Проекты/2026» → «Проекты/2026»; обычная фраза
    папкой не считается;
  - `split_folder_title(title, folders)` — отделяет папку, если модель
    положила её в заголовок: «Люди/101 Александр Шевчук» → заголовок
    «101 Александр Шевчук», папка «Люди». Заголовки вроде «Q3/Q4 итоги»
    не трогаются.
- `app/actions.py` — у команды `create_note` появился необязательный параметр
  `folder`: если пользователь называет папку, модель передаёт её отдельно,
  а `title` остаётся без пути.
- `app/bot.py`:
  - при создании бот сразу показывает до трёх подсказанных папок кнопками
    (модель + название из заголовка), затем Inbox, «Автоопределение»,
    «Другая папка» и «Отмена»; «Автоопределение» больше не единственный путь
    к вариантам;
  - на шаге выбора папки текст пользователя — это папка: «создай папку люди
    и добавь туда» понимается как «Люди» и не уходит в модель;
  - если подсказанной папки нет, кнопка ведёт к вопросу «Папки «Люди» пока
    нет. Создать её и сохранить заметку…?» — то есть создать папку
    предлагает сам бот;
  - папка из заголовка или из аргумента модели видна в превью («Папка: Люди»),
    но остаётся изменяемой кнопками.

## Внешние действия

Не требовались: ключи, LLM и тестовый vault уже настроены. Новые переменные
имеют безопасные значения по умолчанию; менять `.env` не обязательно.

## Принятые решения

- **Подтверждения — по `AGENT_CONFIRMATION`** (ADR-15). В `auto` простой
  сценарий «создать заметку в Inbox» выполняется после нажатия папки без
  второго вопроса, а правки существующих заметок и совпадение имён всегда
  требуют подтверждения.
- **Создание — двухфазное**: сначала папка, потом запись (FR-04.1). Превью
  текста показывается до выбора папки, поэтому пользователь видит, что будет
  записано.
- **Автоопределение не выбирает молча** (ADR-17): модель возвращает до трёх
  папок, бот показывает их кнопками вместе с Inbox. Нет кандидатов — вопрос.
- **Подсказки папок показываются сразу** (ADR-35, правка после Этапа 7).
  Раньше варианты появлялись только после «Автоопределения», а модель, положив
  папку в заголовок (`Люди/Имя`), теряла её при слагификации. Теперь папка из
  заголовка отделяется, подсказки (включая новую папку) видны до нажатия, а
  папка без подтверждения не создаётся.
- **«Другая папка» — текстовый ввод.** Пока действие ждёт папку, следующий
  текст пользователя считается папкой, но разбирается: служебные слова
  («создай», «папку», «туда») отбрасываются, существующая папка берётся в её
  написании. Если папки в тексте нет (это фраза), бот переспрашивает.
- **Изменение — только по разделам** (ADR-16): полная перезапись не
  выполняется; `replace_section` сохраняет frontmatter и соседние разделы.
  Дубль заголовка — ошибка, а не «первый попавшийся».
- **Состояние ожидания привязано к сообщению с кнопками** (ADR-21): двойной
  клик не создаёт две заметки, кнопки старого предложения не срабатывают.
- **Ошибки — по коду ответа** (ADR-19), сообщение короткое и с действием;
  подробности в лог, секреты не логируются.
- **Новая папка — только после подтверждения** (FR-04.4). Проверяется
  `folder_exists()`; исключение — Inbox: он создаётся молча, как разрешает
  FR-04.2. Существующая папка в режиме `auto` не требует лишнего вопроса.
- **Дописывание — по смыслу, а не только в конец** (ADR-22): модель читает
  заметку и передаёт раздел; бот дописывает в его конец. Текст, который в
  заметке уже есть, не дублируется.
- **Лимиты против «разгона»**: 6 шагов агента, 3 варианта папки, 50 папок в
  подсказке, 500 файлов и 3 уровня обхода, 4000 символов прочитанной заметки.

## Ограничения этапа

- **Кандидаты поиска в свободном диалоге — текстом.** Кнопки выбора заметки
  есть только в сценариях «Дописать» и «Править раздел»; агент в ответе
  перечисляет найденное списком.
- **Поиск по именам — по подстроке, без опечаток.** «мария» найдёт
  `Мария.md`, но «мрия» — уже нет; нечёткое сравнение не делалось.
- **Правка раздела показывает новое содержимое**, а не unified diff:
  пользователь видит, что будет записано, но не построчную разницу (FR-03.4
  допускает «diff или краткое описание»).
- **Повторов для идемпотентных чтений нет** (FR-08): ошибки `5xx` и сетевые
  сбои сразу возвращаются пользователю. Ограниченные ретраи — Этап 9.
- **При занятом имени предлагаются «Дописать» и «Отмена».** Выбор другого
  имени — повторная просьба с уточнением, отдельного поля ввода нет.
- **Связи (FR-05, FR-06, FR-10) появились на Этапе 7** — см.
  [08_links.md](08_links.md).

## Как проверить

```powershell
cd E:\FOLDER\TG-OBS\TG_2_Obsidian
.\.venv\Scripts\python.exe -m app --check-config      # видны agent_* настройки
.\.venv\Scripts\python.exe -m app
```

В Telegram (dry-run включён, реальных записей нет):

1. «Сохрани мысль: …» → превью и кнопки папок → «Inbox» → ответ
   «Dry-run: заметка … не записана».
2. То же, «Автоопределение» → до трёх папок кнопками → выбор → dry-run.
3. То же, «Другая папка» → «Напишите папку…» → `Проекты/2026` → путь
   `Проекты/2026/<Заголовок>.md`.
4. «Допиши в заметку TG-OBS smoke test.md: …» → превью и «Подтвердить» →
   «Dry-run: изменения … не записаны».
5. «Что в заметке TG-OBS smoke test.md?» → поиск, чтение, ответ по тексту.
6. Повторное нажатие кнопки → «Это предложение устарело…».
7. Остановить Obsidian и повторить п. 1 → сообщение «Не удалось связаться с
   Obsidian…», бот продолжает работать.
8. Попросить дописать текст, который в заметке уже есть → «Такой текст в
   заметке уже есть — дубликат не добавляю», файл не меняется.
9. Нажать кнопку «Новый диалог» → история и ожидания очищены, в чате снова
   клавиатура; кнопки «Справка» и «Начать заново» работают как `/help`
   и `/start`. При наборе `/` в поле ввода видны те же три команды.
10. «📝 Новая заметка» → прислать текст → превью и кнопки папок → «Inbox» →
    заметка создана (или dry-run).
11. «➕ Дописать» → написать «Проект» → бот найдёт заметку → выбрать раздел
    кнопкой → прислать текст → подтверждение → текст в выбранном разделе.
12. «✏️ Править раздел» → заметка → раздел → новый текст → подтверждение.
    «🔎 Найти» → слово → бот показывает заметку.

Шаги 10–12 задают команду кнопкой, но текст всё равно проходит через модель:
она переписывает его под заметку и раздел, поэтому результат может отличаться
от присланного.

13. Прислать непонятное («ну не знаю») → бот переспрашивает и показывает
    кнопки действий (`clarify`).
14. Прислать готовую мысль без команды → модель сама выбирает `create_note`
    и предлагает заметку с развёрнутым текстом.

Правка после Этапа 7 (подсказки папок):

15. Создать карточку человека так, чтобы модель предложила заголовок
    `Люди/101 Александр Шевчук`: в превью видно «Папка: Люди», а первой
    кнопкой — «Люди». Нажать её при отсутствии папки → «Папки «Люди» пока
    нет. Создать её и сохранить заметку «Люди/101 Александр Шевчук.md»?».
16. На шаге «Куда сохранить?» прислать «Создай папку люди и добавь туда» →
    бот не повторяет предложение, а спрашивает про создание папки «Люди»
    (если папка уже есть — сразу строит путь `Люди/…`).
17. На том же шаге прислать фразу без папки («нет, перепиши короче») → бот
    просит выбрать папку кнопкой и не уходит в модель.
18. Кнопка «Отмена» на шаге папки → заметка не создаётся.

Юнит-тесты правки: `tests/test_folders.py` — разбор ответа, папка из
заголовка, очистка пути (`../evil`, пустые сегменты, `\`).

Добавление новой команды: запись в `app/actions.py` + обработчик в
`app/agent.py`; промпт и схемы инструментов обновятся автоматически.

Проверено на этапе: все сценарии выше с поддельными Telegram-объектами
(создание, занятое имя → дописывание, автоопределение, своя папка, режим
`always`, отмена, устаревшая кнопка) и три живых прогона с моделью: создание
заметки (preview → Inbox → dry-run), дописывание (`search_notes` →
предложение → подтверждение → dry-run), чтение (`search_notes` → `read_note` →
ответ). Форматирование разделов проверено на синтетических заметках:
frontmatter, пустые строки и соседние разделы сохраняются.

После перехода на реестр проверено с подставной моделью: `clarify`
возвращает вопрос и флаг уточнения; `compose_note` разбирает заголовок из
Markdown; `compose_append` подставляет переписанный фрагмент в превью, а
кнопочный сценарий «Новая заметка» отправляет в заметку результат модели,
а не исходный текст.

## Риски и откат

- Риск: при `OBSIDIAN_DRY_RUN=false` подтверждённая запись выполняется сразу.
  Откат — удалить заметку в Obsidian; перезапись существующей запрещена
  клиентом.
- Риск: «Другая папка» перехватывает следующее сообщение. Если оно не похоже
  на путь, бот ответит ошибкой проверки пути и ничего не запишет.
- Риск: модель предлагает неудачный заголовок → неудачное имя файла. Видно в
  превью до записи; переименование — вручную или повторной просьбой.
- Риск: автоопределение тратит дополнительный запрос к LLM (на free-тарифе
  это 1 из 50 в сутки).
- Риск: заметка больше 4000 символов читается частично — модель может не
  увидеть конец. Постраничное чтение — при необходимости на Этапе 6–7.
- Риск: параллельные правки из Obsidian во время read-modify-write. При одном
  пользователе и коротком окне между чтением и записью риск мал; блокировок
  нет.
- Откат кода: убрать `app/agent.py` и `app/notes.py`, вернуть прямой вызов
  `llm.chat()` в `answer_text()`, убрать обработчики кнопок и настройки
  `AGENT_*`. Заметки, созданные агентом, удаляются вручную.
