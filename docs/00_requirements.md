# Этап 0: Уточнение требований и проверка окружения

## Этап

Этап 0 — «Уточнение требований и проверка окружения». Оформлен задним числом:
на момент согласования требования к папке `docs/` ещё не были заданы.

## Цель

Зафиксировать требования и окружение до написания кода, чтобы не менять
архитектуру в середине работы.

## Что сделано

- Проверено окружение: Windows (win32), Python 3.14.4 в PATH, git 2.53.0,
  папка проекта `E:\FOLDER\TG-OBS` пустая.
- Согласованы ответы на вопросы этапа (см. «Принятые решения»).
- Составлен план из 11 этапов (0–10), он отражён в [README.md](README.md).
- Позже, при уточнении Этапов 5–7, добавлены функциональные требования
  (см. ниже и [FEATURES.md](FEATURES.md)).

## Функциональные требования (дополнено 2026-10-27)

Целевое поведение Этапов 5–7 зафиксировано в [FEATURES.md](FEATURES.md).
Добавлены функции:

- **FR-01. Создание новой заметки** — заголовок, содержимое, папка; защита от
  перезаписи; показ пути.
- **FR-02. Добавление в существующую заметку** — поиск по контексту, показ
  кандидатов, дописывание без потери существующего текста.
- **FR-03. Изменение существующей заметки** — добавление и правка выбранного
  раздела (read-modify-write), без полной перезаписи по умолчанию.
- **FR-04. Автоматическое расположение** — кнопки «Inbox» и
  «Автоопределение»; авторежим использует контекст и структуру папок, при
  неоднозначности уточняет.
- **FR-05. Автопростановка связей** при создании и изменении; при
  неоднозначности — уточнение.
- **FR-06. Простановка связей во всех заметках** — отдельная массовая
  операция с планом и подтверждением.
- **FR-07. Глобальная настройка подтверждений** — `AGENT_CONFIRMATION`:
  `auto` (по умолчанию), `always`, `never`.
- **FR-08. Обработка ошибок API и сервера** — классификация ошибок,
  понятные сообщения, отсутствие дублей и частичных записей.
- **FR-09. Поиск заметок по контексту** — полнотекстовый поиск до внедрения
  RAG.
- **FR-10. Правила связей** — только существующие заметки, без самоссылок и
  дублей, раздел `## Связи`.

## Внешние действия

От пользователя получены ответы:

- запуск сейчас на ПК, позже перенос на NAS;
- Obsidian настроим по инструкции наставника (плагин ещё не установлен);
- LLM — внешний провайдер, бесплатный или очень дешёвый, с быстрой сменой
  модели;
- RAG — позже;
- пути проекта остаются как есть, git подключает пользователь;
- При уточнении Этапов 5–7 выбраны: подтверждения только при сомнениях или
  неоднозначности; расположение — кнопки «Inbox» и «Автоопределение»;
  изменение — добавление и правка раздела; поиск — полнотекстовый.

## Принятые решения

- Стек по умолчанию сохранён: Python 3.14.4 (системный), `aiogram 3.x`,
  OpenAI-совместимый API, Obsidian Local REST API.
- Код пишется кроссплатформенно (`pathlib`, без Windows-специфичных вызовов),
  чтобы перенос на NAS не потребовал переписывания.
- Docker на этом этапе не вводится: при запуске на одном ПК это лишняя сложность.
  Решение вернуть перед переносом на NAS.
- RAG откладывается на Этап 8: до рабочего агента и автолинковки он не нужен;
  поиск по контексту до него — полнотекстовый (ADR-18).
- Разработка ведётся только против тестового vault; рабочий vault подключается
  последним и по явному разрешению.
- Подтверждения — по глобальной настройке `AGENT_CONFIRMATION`. По умолчанию
  `auto`: спрашивать только при сомнениях или неоднозначности, ничего не
  додумывать (ADR-15).
- Изменение существующей заметки — добавление и правка выбранного раздела,
  без полной перезаписи (ADR-16).
- Расположение новых заметок — кнопками «Inbox» и «Автоопределение»; Inbox —
  безопасный вариант по умолчанию, авторежим — по контексту и структуре
  папок, с уточнением (ADR-17).
- Поиск существующей заметки — полнотекстовый; RAG остаётся опциональным
  Этапом 8 (ADR-18).
- Ошибки API/сервера обрабатываются явно: сообщение пользователю, лог без
  секретов, повторы только для безопасных операций (ADR-19).
- Связи — автолинковка при создании/изменении и массовая операция с
  подтверждением; формат — раздел `## Связи` (ADR-20).

## Как проверить

```powershell
python --version

```

Ожидается Python 3.1x и git 2.x.

## Риски и откат

- Python 3.14 может не иметь готовых сборок части пакетов (актуально для RAG).
  Откат: отдельный venv с Python 3.12, только по согласованию.
- Риск: полнотекстовый поиск на большом vault медленный. Ограничить выдачу
  `AGENT_SEARCH_LIMIT` и использовать Search API плагина.
- Риск: массовая простановка связей затрагивает много заметок. План,
  подтверждение, dry-run и идемпотентность обязательны.
- Риск: частичная запись при сбое API. Изменения — read-modify-write,
  результат проверяется, ошибка не считается успехом.
- Откатывать нечего: на этапе не создавалось файлов проекта.
