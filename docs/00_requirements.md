# Этап 0: Уточнение требований и проверка окружения

## Этап

Этап 0 — «Уточнение требований и проверка окружения». Оформлен задним числом:
на момент согласования требования к папке `docs/` ещё не были заданы.

## Цель

Зафиксировать требования и окружение до написания кода, чтобы не менять
архитектуру в середине работы.

## Что сделано

- Проверено окружение: Windows (win32), Python 3.14.4 в PATH, git 2.53.0,
  папка проекта `E:\FOLDER\TG-OBS` пустая.
- Согласованы ответы на вопросы этапа (см. «Принятые решения»).
- Составлен план из 11 этапов (0–10), он отражён в [README.md](README.md).

## Внешние действия

От пользователя получены ответы:

- запуск сейчас на ПК, позже перенос на NAS;
- Obsidian настроим по инструкции наставника (плагин ещё не установлен);
- LLM — внешний провайдер, бесплатный или очень дешёвый, со быстрой сменой модели;
- RAG — позже;
- пути проекта остаются как есть, git подключает пользователь.

## Принятые решения

- Стек по умолчанию сохранён: Python 3.14.4 (системный), `aiogram 3.x`,
  OpenAI-совместимый API, Obsidian Local REST API.
- Код пишется кроссплатформенно (`pathlib`, без Windows-специфичных вызовов),
  чтобы перенос на NAS не потребовал переписывания.
- Docker на этом этапе не вводится: при запуске на одном ПК это лишняя сложность.
  Решение вернуть перед переносом на NAS.
- RAG откладывается на Этап 8: до рабочего агента и автолинковки он не нужен.
- Разработка ведётся только против тестового vault; рабочий vault подключается
  последним и по явному разрешению.

## Как проверить

```powershell
python --version
git --version
```

Ожидается Python 3.1x и git 2.x.

## Риски и откат

- Python 3.14 может не иметь готовых сборок части пакетов (актуально для RAG).
  Откат: отдельный venv с Python 3.12, только по согласованию.
- Откатывать нечего: на этапе не создавалось файлов проекта.
