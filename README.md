## Что это

**TG-OBS** — личный ассистент для Obsidian, который живёт в Telegram. Вы
пишете «запиши мысль…», «допиши в заметку про…», «что я писал про сроки
релиза?» — бот находит нужную заметку, выбирает раздел, оформляет текст по
вашему шаблону, предлагает связи и показывает превью перед записью.

Это не бот с жёстким набором команд. Модель получает список инструментов
(`search_notes`, `create_note`, `append_note`, `edit_section`, `add_links` и
другие) и вызывает их по смыслу. Формулировка может быть любой, неоднозначные
места бот уточняет, а не додумывает.

Проект задуман как **ваш**: стиль письма, шаблоны, папки, правила связей,
подтверждения и модели настраиваются через `.env` и заметки в хранилище —
без правки кода. Код нужен только для новых команд агента и изменения
системного промпта.

Работает в трёх режимах хранилища:

- **`auto`** (по умолчанию) — сначала Local REST API, при его недоступности
  файлы, с возвратом к API, когда он снова отвечает;
- **`vault`** — только `.md`-файлы напрямую. Obsidian может быть закрыт,
  плагины и ключ не нужны;
- **`rest`** — только плагин Local REST API: нужен запущенный Obsidian, зато
  доступны его поиск, алиасы и теги.

## Возможности

| Возможность | Что делает |
|---|---|
| **Понимает речь** | «сохрани это», «поправь там», «что я писал про…» — контекст диалога учитывается |
| **Создаёт заметки** | по шаблону или без, в вашем стиле, с frontmatter и подставленной датой |
| **Дополняет и правит** | дописывает в нужный раздел, заменяет раздел, удаляет строку, ссылку или абзац; пустой результат очищает раздел |
| **Управляет структурой** | создаёт разделы и папки, переименовывает, переносит, копирует и удаляет заметки |
| **Ставит связи** | подбирает `[[ссылки]]` на существующие заметки и проставляет их во всём хранилище одной операцией |
| **Ищет по смыслу** | локальные эмбеддинги находят заметку, даже если точных слов в ней нет. Без облака |
| **Переживает лимиты** | пул аккаунтов и моделей: `429` → следующий аккаунт, потом следующая модель, затем автосброс |
| **Работает без Obsidian** | файловый режим не требует запущенного приложения и плагинов |
| **Закрыт для чужих** | отвечает только id из `TELEGRAM_ALLOWED_USERS`, остальным молчит и пишет отказ в лог |
| **Не ломает заметки** | dry-run по умолчанию, подтверждения, read-modify-write, атомарная запись, корзина вместо стирания |
| **Не верит модели слепо** | рассуждения модели вместо текста распознаются и не записываются |
| **Переживает сбои** | повтор чтений при сети/`5xx`, резервный файловый режим, ошибки не обрывают диалог |
| **Показывает, что сломано** | `--health` проверяет Telegram, хранилище, LLM, RAG, журнал, копии, доступ |
| **Сохраняет копии** | zip хранилища и журнала по расписанию, без секретов, с ротацией |
| **Разворачивается где угодно** | Docker-образ и `docker compose` для NAS/VPS, CI на каждый push |

## Пример диалога

```text
Вы:  запиши мысль: на созвоне решили сдвинуть релиз на неделю,
     не успеваем с тестами

Бот: Предлагаю заметку «Сдвиг релиза»:
     ...
     Куда сохранить?
     [ Inbox ]  [ Автоопределение ]  [ Другая папка ]

Вы:  Inbox

Бот: Заметка создана: Inbox/Сдвиг релиза.md.
     [ Добавить связи ]  [ Не сейчас ]
```

Если папка новая или включён `AGENT_CONFIRMATION=always`, бот сначала спросит
«Создать заметку …?» с кнопками «Подтвердить» и «Отмена».

Поиск тоже понимает смысл, а не только слова:

```text
Вы:  что я писал про сроки релиза?

Бот: Нашёл: Projects/Проект Альфа.md — «релиз сдвигается на неделю
     из-за тестов…» (по смыслу)
```

## Как это работает

```mermaid
flowchart LR
    TG(["Telegram"]) --> BOT["aiogram 3<br/>бот, кнопки, сценарии"]
    BOT --> AGENT["Агент<br/>tool-calling, до 6 шагов"]
    AGENT --> POOL["LLM-пул<br/>аккаунты × модели"]
    AGENT --> BACKEND["ObsidianBackend<br/>единый интерфейс"]
    BACKEND --> REST["Local REST API"]
    BACKEND --> FILES["Файлы vault<br/>.md напрямую"]
    AGENT --> RAG["RAG<br/>sentence-transformers"]
    RAG --> IDX[("state/rag<br/>локальный индекс")]
```

Ключевая деталь: **модель не пишет в хранилище напрямую**. Она вызывает
инструменты, а изменение выполняет бот — после превью и подтверждения, через
общий `ObsidianBackend`. Поэтому ошибка модели не превращается в испорченную
заметку.

## Быстрый старт

Нужен только Python 3.11+ (RAG — опционально). Для NAS и VPS есть готовый
Docker-образ, см. ниже.

```powershell
git clone https://github.com/gZEVI-1/TG_2_Obsidian.git
cd TG_2_Obsidian

python -m venv .venv
.\.venv\Scripts\Activate.ps1        # Windows PowerShell
# source .venv/bin/activate         # macOS / Linux

pip install -r requirements.txt
Copy-Item .env.example .env         # macOS / Linux: cp .env.example .env
# заполните .env: токен Telegram, ключ LLM, путь к хранилищу

python -m app --check-config        # настройки в порядке?
python -m app --health              # что видно: Telegram, хранилище, копии
python -m app                       # запуск
```

Минимум, что нужно вписать в `.env`:

```ini
TELEGRAM_BOT_TOKEN=123456789:AA...
TELEGRAM_ALLOWED_USERS=123456789   # свой id: @userinfobot

LLM_STUB=false
LLM_API_1_BASE_URL=https://openrouter.ai/api/v1
LLM_API_1_KEY=sk-or-v1-...
LLM_MODELS=nvidia/nemotron-3-ultra-550b-a55b:free

OBSIDIAN_MODE=vault
OBSIDIAN_VAULT_PATH=C:/Users/me/Documents/MyVault
OBSIDIAN_DRY_RUN=true
```

> **Впервые запускаете бота?** В [INSTALL.md](docs/INSTALL.md) разобраны
> BotFather, ключ OpenRouter, хранилище Obsidian, режим REST, проверки и
> типичные ошибки — по шагам, без предположений.

### Docker: NAS, VPS и чистый запуск

```bash
git clone https://github.com/gZEVI-1/TG_2_Obsidian.git
cd TG_2_Obsidian
cp .env.example .env     # токен, ключи; OBSIDIAN_MODE=vault
docker compose up -d --build
docker compose logs -f bot
```

Пути на хосте задаются в `.env` (прямые слэши): `VAULT_PATH=/volume1/obsidian/MyVault`,
`BACKUP_PATH=/volume1/docker/tg-obs/backups`. Внутри контейнера бот работает
не от root, с часовым поясом `TZ` (по умолчанию `Asia/Dubai`), а
`restart: unless-stopped` поднимает его после перезагрузки. Подробности и
запуск без Docker (systemd) — [docs/16_ci_docker.md](docs/16_ci_docker.md).

## Сделать под себя

Почти всё меняется без кода. Порядок — от самого заметного к тонкому.

### 1. Свой стиль письма

Бот переписывает текст под вашу манеру, если в хранилище есть заметка-описание:

```ini
AGENT_STYLE_NOTE=Templates/Мой стиль.md
```

В ней обычным текстом: тон, структура, оформление, чего избегать. Подробный
пример и разбор — [docs/PROMPTS.md](docs/PROMPTS.md#1-стиль-письма-заметка-описание).

### 2. Свои шаблоны заметок

Положите `.md`-шаблоны в папку хранилища (по умолчанию `Templates`) и укажите
её:

```ini
AGENT_TEMPLATE_FOLDER=Templates
```

Бот предложит до шести шаблонов кнопками и заполнит разделы по смыслу.
Плейсхолдеры `{{title}}`, `{{date}}`, `{{time}}` подставляет бот, Templater не
выполняется. Как писать шаблоны — [docs/PROMPTS.md](docs/PROMPTS.md#2-шаблоны-заметок)
и [docs/07_templates_style.md](docs/07_templates_style.md).

### 3. Подтверждения и поведение

| Задача | Настройка |
|---|---|
| Спрашивать только при неоднозначности (по умолчанию) | `AGENT_CONFIRMATION=auto` |
| Спрашивать перед каждой записью | `AGENT_CONFIRMATION=always` |
| Никогда не спрашивать | `AGENT_CONFIRMATION=never` |
| Папка для кнопки «Inbox» | `AGENT_DEFAULT_FOLDER=Inbox` |
| Скрыть «Автоопределение» | `AGENT_AUTO_FOLDER=false` |
| Сколько кандидатов показывать при поиске | `AGENT_SEARCH_LIMIT=5` |

Очистка раздела всегда показывается в превью и требует подтверждения, даже
при `never`: пустой ответ модели не должен стирать текст молча.

### 4. Связи

```ini
AGENT_AUTO_LINK=true      # предлагать связи при создании и правке
AGENT_LINK_LIMIT=10       # максимум ссылок на заметку
```

Массовая простановка — кнопка «🔗 Связи во всех заметках» или `/links`.
Правила и ограничения — [docs/08_links.md](docs/08_links.md).

### 5. Модели и аккаунты

Можно указать несколько API-аккаунтов и несколько моделей. При `429` запрос
уходит на следующий аккаунт той же модели, затем на следующую модель, после
всех — автосброс к лучшей. Настройка и поведение —
[docs/LLM_POOL.md](docs/LLM_POOL.md). Бесплатные модели подходят, но чаще
упираются в лимиты.

### 6. Хранилище и доступ

| Задача | Настройка |
|---|---|
| REST первым, файлы — резерв | `OBSIDIAN_MODE=auto` + ключ + путь |
| Только файлы, Obsidian закрыт | `OBSIDIAN_MODE=vault` |
| Только REST API | `OBSIDIAN_MODE=rest` + `OBSIDIAN_API_KEY` |
| HTTPS с самоподписанным сертификатом | `OBSIDIAN_BASE_URL=https://…:27124` + `OBSIDIAN_VERIFY_SSL=false` |
| Кто может пользоваться ботом | `TELEGRAM_ALLOWED_USERS=id1,id2` |
| Реальная запись | `OBSIDIAN_DRY_RUN=false` |

Пустой `TELEGRAM_ALLOWED_USERS` означает «отвечать любому чату» — так сделано,
чтобы обновление не блокировало владельца. Свой id покажет **@userinfobot**.

### 7. Свои команды и промпт

Системный промпт и список инструментов живут в коде (`app/actions.py`,
`app/agent.py`), но расширять их просто: добавить `Action` в реестр, обработать
имя в агенте и пометить `writes=True`, если команда меняет заметки. Правила
для модели и примеры — [docs/PROMPTS.md](docs/PROMPTS.md#3-системный-промпт).

## Настройки

Все параметры читаются из `.env` и проверяются при старте: опечатка в
`true/false` или неверный режим — понятная ошибка, а не молчаливая подстановка.
Полный шаблон с комментариями — [`.env.example`](.env.example); порядок
разделов там совпадает с рабочим `.env`.

### Подключение, модель и хранилище

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | токен бота от [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_ALLOWED_USERS` | — | числовые id через запятую; пусто — отвечать всем |
| `LLM_STUB` | `false` | режим заглушек: сеть и ключи не нужны, но заметки не создаются |
| `LLM_MODELS` | список из `.env.example` | модели через запятую, **первая — лучшая** |
| `LLM_API_<N>_BASE_URL` | — | OpenAI-совместимый endpoint, например `https://openrouter.ai/api/v1` |
| `LLM_API_<N>_KEY` | — | ключ аккаунта `N` (нумерация с 1) |
| `LLM_API_<N>_NAME` | `account-N` | имя аккаунта для `/llm` |
| `LLM_COOLDOWN_SECONDS` | `3600` | пауза пары при `429` без `Retry-After` |
| `OBSIDIAN_MODE` | `auto` | `auto` — REST, затем файлы; `vault` / `rest` — принудительно |
| `OBSIDIAN_VAULT_PATH` | — | путь к папке хранилища (для `vault` и резерва в `auto`) |
| `OBSIDIAN_BASE_URL` | `http://127.0.0.1:27123` | адрес Local REST API |
| `OBSIDIAN_API_KEY` | — | ключ плагина Local REST API |
| `OBSIDIAN_VERIFY_SSL` | `true` | проверять сертификат HTTPS; `false` — только для своего самоподписанного |
| `OBSIDIAN_DRY_RUN` | `true` | `true` — только читать и показывать план, без записи |

### Агент, шаблоны и поиск

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AGENT_CONFIRMATION` | `auto` | `auto` / `always` / `never` |
| `AGENT_DEFAULT_FOLDER` | `Inbox` | папка для кнопки «Inbox» |
| `AGENT_AUTO_FOLDER` | `true` | показывать кнопку «Автоопределение» |
| `AGENT_TEMPLATE_FOLDER` | `Templates` | папка с шаблонами в хранилище |
| `AGENT_STYLE_NOTE` | — | путь к заметке с описанием вашего стиля |
| `AGENT_AUTO_LINK` | `true` | предлагать связи при создании и правке |
| `AGENT_LINK_LIMIT` | `10` | максимум ссылок на заметку |
| `AGENT_SEARCH_LIMIT` | `5` | сколько кандидатов показывать при поиске |
| `RAG_ENABLED` | `true` | семантический поиск (нужен `requirements-rag.txt`) |
| `RAG_MODEL` | `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` | модель эмбеддингов |
| `RAG_TOP_K` | `5` | сколько смысловых совпадений добавлять |

### Эксплуатация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LOG_LEVEL` | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` / `CRITICAL` |
| `LOG_FILE` | `state/logs/app.log` | файл лога (ротация 2 МБ × 5); пусто — только консоль |
| `BACKUP_DIR` | — | папка копий; пусто — `--backup` и автокопии выключены |
| `BACKUP_KEEP` | `7` | сколько последних копий хранить |
| `BACKUP_EVERY_HOURS` | `24` | копия при старте, если просрочена, и проверка раз в час; `0` — только вручную |
| `AUDIT_ENABLED` | `true` | журнал изменений `state/audit/` |
| `OBSIDIAN_RETRY_ATTEMPTS` | `3` | повторы чтений при сети/`5xx` |
| `OBSIDIAN_RETRY_DELAY_SECONDS` | `0.5` | база паузы между повторами |
| `OBSIDIAN_FAILOVER_SECONDS` | `30` | пауза перед повторной проверкой REST после сбоя |

> В `.env.example` стоит `LLM_STUB=true`, чтобы бот запускался без ключей. Для
> реальной работы поставьте `LLM_STUB=false` и заполните `LLM_API_1_*` — иначе
> бот будет отвечать «Заглушка LLM» и не сможет создавать заметки.

## Команды и кнопки

Внизу чата две страницы кнопок: главная и сценарии работы с заметками.
Сценарии идут по шагам и не требуют, чтобы модель угадывала смысл.

| Команда | Что делает |
|---|---|
| `/start` | начать заново, очистить контекст |
| `/new` | новый диалог и переход к сценариям |
| `/help` | справка по кнопкам и возможностям |
| `/folders` | список папок хранилища |
| `/links` | план и массовая простановка связей |
| `/rag` | состояние семантического поиска |
| `/reindex` | пересобрать RAG-индекс |
| `/llm` | активная модель, аккаунт, лимиты и время автосброса |
| `/llm_reset` | снять лимиты и вернуться к лучшей модели |
| `/audit` | последние изменения хранилища |

| Страница | Кнопки |
|---|---|
| Главная | «Остаться в этом чате», «Новый диалог», «Начать заново», «Справка» |
| Сценарии | «Новая заметка», «Дописать», «Править раздел», «Найти», «Папки», «Связи во всех заметках», «Назад» |

Служебные команды — из корня проекта:

```powershell
python -m app --check-config      # настройки, без сети
python -m app --check-obsidian    # хранилище + тестовая запись
python -m app --check-llm         # ответ модели и поддержка tool-calls
python -m app --check-rag         # эмбеддинги, индекс, пробный поиск
python -m app --health            # готовность: Telegram, хранилище, LLM, RAG, копии, доступ
python -m app --backup            # резервная копия в BACKUP_DIR
```

`--check-obsidian` создаёт в хранилище заметку `TG-OBS smoke test.md` — если
`OBSIDIAN_DRY_RUN=false`. Её можно удалить.

## Эксплуатация

- **Что сломано — одной командой.** `python -m app --health` проверяет токен
  через `getMe`, оба бэкенда хранилища, LLM-настройки, RAG, доступность
  `state/audit`, каталог копий, локальность REST и лог. Критичные ошибки дают
  код возврата 2.
- **Журнал в файл.** `state/logs/app.log`, ротация 2 МБ × 5. Если файл
  недоступен, лог остаётся в консоли.
- **Копии.** `--backup` делает zip хранилища и журнала без `.env`, `.obsidian`
  и индекса RAG. Пока бот запущен, копия делается сама по
  `BACKUP_EVERY_HOURS` (24 ч по умолчанию): при старте, если просрочена, и
  далее раз в час.
- **Аудит.** Все изменения пишутся в `state/audit/YYYY-MM-DD.jsonl` — без
  содержимого заметок. Агент этот журнал не читает.
- **Обновление.** `git pull`, `pip install -r requirements.txt`, перезапуск.
  Для Docker: `git pull && docker compose up -d --build`. `.env`, шаблоны и
  индекс RAG не затрагиваются.
- **Логи Docker.** `docker compose logs -f bot`.

## Надёжность и безопасность

- **Dry-run по умолчанию.** С `OBSIDIAN_DRY_RUN=true` бот читает хранилище,
  показывает план и превью, но ничего не пишет.
- **Никакой полной перезаписи.** Правка — read-modify-write выбранного раздела:
  frontmatter, остальные разделы и ссылки сохраняются.
- **Удаление обратимое.** В файловом режиме объект уходит в `.trash`, в
  REST-режиме — в корзину Obsidian.
- **Ошибка не считается успехом.** Если API вернул ошибку, пользователь видит
  сообщение, а операция не подтверждается как выполненная.
- **Доступ ограничен.** Бот отвечает только id из `TELEGRAM_ALLOWED_USERS`,
  остальным молчит, а отказ с id пишется в лог. Список читается при старте.
- **Модель не пишет напрямую.** Инструменты возвращают предложение, запись
  выполняет бот после подтверждения.
- **Рассуждения модели не записываются.** Ответ проверяется на цитаты
  инструкции и смену языка; пустой результат замены раздела означает очистку
  и всегда показывается в превью.
- **Секреты — только в `.env`.** Файл в `.gitignore`; в логах и сообщениях
  ключей нет — только факт наличия и длина.
- **Внешняя модель видит текст заметок.** При поиске и создании фрагменты
  отправляются выбранному провайдеру. Для чувствительных данных используйте
  локальную модель.
- **REST только локально.** `127.0.0.1` по умолчанию; для удалённого доступа —
  HTTPS с проверкой сертификата или SSH-туннель, не открытый порт.
- **Один процесс на токен.** Второй long-polling клиент получит `409 Conflict`.

## Ограничения

- Список заметок и папок ограничен **500 файлами и 3 уровнями** вложенности.
- В модель попадает не больше **4000 символов** заметки, шаблона и стиля.
- В кнопках показывается до **6 шаблонов** (по алфавиту); остальные доступны
  в свободном диалоге.
- История диалога — **20 сообщений**, живёт в памяти и теряется при
  перезапуске.
- RAG при первом запуске скачивает модель **~470 МБ**; без сети бот продолжит
  работать с обычным поиском.
- `Templater`-шаблоны не выполняются: плейсхолдеры подставляет бот.
- В режиме `rest` Obsidian должен быть запущен; в `vault` — нет.
- Long polling, без webhook: машина с ботом должна быть включена.
- Копии делаются, только пока бот запущен; если месяц не запускать — копий за
  этот месяц не будет.

# тесты: 252 штуки, без сети и без секретов

Те же тесты гоняет CI на Python 3.11, 3.12 и 3.13 при каждом push; отдельная
job собирает Docker-образ. Локально RAG-тесты идут, если установлен
`requirements-rag.txt`, иначе пропускаются.

**Как добавить команду агенту.** Инструменты и блок промпта собираются из
одного реестра, поэтому достаточно:

1. добавить `Action` в `ACTIONS` (`app/actions.py`) — имя, описание, JSON-схему;
2. обработать имя в `app/agent.py` — вернуть предложение или выполнить чтение;
3. поставить `writes=True`, если команда меняет заметки: тогда она станет
   терминальной и выполнится только после подтверждения.

## FAQ

### Нужен ли запущенный Obsidian?

Нет, если выбран режим `vault` или `auto` с указанным путём: бот пишет файлы
напрямую. В режиме `rest` — да, Local REST API живёт внутри приложения.

### Можно ли пользоваться бесплатно?

Да: подойдут бесплатные модели OpenRouter (с лимитами), а RAG работает
локально. Платный ключ не обязателен, но бесплатные модели отвечают медленнее
и чаще упираются в `429` — пул это переживает.

### Где работает бот?

На вашем компьютере, NAS или VPS — нативно или в Docker. Telegram — только
интерфейс; пока машина выключена, бот не отвечает.

### Можно ли дать доступ друзьям?

Да, впишите их id в `TELEGRAM_ALLOWED_USERS`. Разделения прав пока нет: все
разрешённые получают доступ к одному хранилищу и могут его менять.

### Куда деваются удалённые заметки?

В файловом режиме — в папку `.trash` внутри хранилища, в REST-режиме — в
корзину Obsidian.

### Как обновить бота?

`git pull`, затем `pip install -r requirements.txt`, перезапуск. Для Docker:
`git pull && docker compose up -d --build`. `.env`, ваши шаблоны и индекс RAG
при обновлении не затрагиваются.

### Что делать, если бот молчит?

`python -m app --health`: он покажет, что именно сломано — токен, хранилище,
доступ, копии. Лог — `state/logs/app.log` (или `docker compose logs -f bot`).
